## 角色身份识别

当前不依赖少量固定名称截图判断候选身份。`AndroidLabyrinthRoleRewardNameResolver` 先读取三名候选的名称，并通过统一角色名称表解析；文字不足以可靠确认时，再调用 `icons.json` 与共享 `LabyrinthCharacterIconMatcher` 做头像回退及必要名称辅助。页面提供左/中/右的名称和头像 ROI，最终仍需通过角色奖励的身份安全判断才允许选择。

下面这些角色名称模板仅作为**历史回归素材**，用于旧截图诊断，不再决定正式流程中的角色身份：

- `characters/character_1335_name.png`：咲恋(新年)，角色 ID `1335`
- `characters/character_1233_name.png`：涅娅，角色 ID `1233`
- `characters/character_1256_name.png`：碧卡拉，角色 ID `1256`

真实随机三选一不再受这三个样本覆盖范围限制。名称与头像证据未达到可信条件时继续等待，不根据“最相似角色”盲选。只读模式不点击；桌面自动执行要求实际截图为 1920×1080 横屏。当前 OCR 真实评估中角色奖励类别仍为 0 个样本，不能把存在这套源码与模板当作该类别质量已验收。
