# 固定模型前处理诊断（2026-10-25）

本轮只使用已固定的 PP-OCRv5 det/rec/字典。未下载、更换模型，未修改原14条真值、resolver裁剪、上游matcher或置信阈值。所有变体均是诊断观察，不增加评估条数；手动框出的数字只用于区分检测和识别失败，不进入生产代码。

## 先纠正比较对象

前轮v4直识别得到5/0.9857481的是`final-boss-active-20260909.jpg`（1920×1080）中的`map-boss-0`，不是低分辨率`node-link-20260914.png`的`map-link-0`。因此不能把该分数与后者失败比较，推导出320宽张量补边造成回归。当前v5原始输入的高分辨率5仍正确；低清5原整图直识别只有G/0.13586323。

## 可复现方法

执行 `desktop/gradlew -p desktop :ocr:diagnosePreprocessing`。源码为`src/test/kotlin/com/landosol/toolbox/desktop/ocr/OcrFailureDiagnosisTest.kt`，常规`:ocr:test`排除该类。显式诊断输出PNG和TSV到`build/reports/preprocessing-diagnosis/`；提交的原始记录为`preprocessing-diagnosis.tsv`。

TSV的`direct`和`detected-N`保留CTC原始文字及平均得分，即使低于0.5也展示；`final`才是当前生产引擎的阈值过滤结果，已包含本轮批准的末级回退。检测框记录在当前变体图像坐标系，人工数字诊断框见源码。未将诊断解码用作实体真值。

真实来源均是已有上游图片：两个低清计数、系列面板、四个1920地图计数。负对照是同一1920地图中的加号、准星、双剑、箭头条和无文字背景；精确坐标在诊断代码和定向回归中。所用变换是最近邻/双线性/双三次缩放、亮度灰度、以128为中点的0.5/1.5对比度、反色、RGB单通道、灰度150/200二值、320/640高且64重叠的纵向块、四周或左右的1/4短边纯黑/白补边。二值像素阈值仅供诊断，未改模型置信门槛。

## 低清计数结果与已采用改动

| 输入 | 原整图直识别（原始分数） | 原检测 | 四周1/4短边黑边的det+rec |
|---|---|---|---|
| 低清5 | G / 0.136 | 无框 | 5 / 0.835 |
| 低清2 | 2 / 0.873 | 无框 | 2 / 0.968 |

双线性、双三次对低清5得到5/0.327和5/0.209，仍低于原0.5；灰度得到百/0.137，还让原正确低清2下降至0.486。白边同样不能恢复低清5。这些方案没有采用。

四周黑边恢复数字定位，与该ROI紧贴绿色图标和边缘的上下文有关。这里是模型响应的实测观察，不声称已证明网络内部机制。最小改动限定于原FB-14紧凑区域：宽高32..256、长宽比0.5..2、非纯色；原检测及一次整图识别都无有效文本时才补边，再做一次det+rec。边宽为`min(width,height)/4`向下取整，原像素不动，检测0.3/0.6与识别0.5阈值不动；不递归、不再对补边图整图识别。已有有效结果立即返回。

这项短路限制必要：强制对所有输入改成黑边会让原高分辨率数字2的检测路径退化为空，虽然其原整图识别为2/0.993。因此本轮没有替换成功路径，也没有修改全局预处理。

五个真实无文字ROI在原路径与补边检测路径均为空；17项正式回归包括这些负对照和低清5/2，并保持既有高分辨率5/4/2/1。负对照只有五处，不能由此证明任意图标都无误识别；新增分支保持有界、现有置信过滤及可诊断日志。纯色图不进入回退。

代价是失败紧凑ROI最多增加一个检测推理及其框的识别推理，补边后宽高不超过384，不增加模型/线程/队列。当前原14评估中低清5耗时31.87 ms，总体p50 23.32 ms / p95 157.57 ms；同机单次结果，未作额外基准或夸大性能保证。

## 系列面板为何仍失败

原`series-visible`为240×1426（上游120×713裁剪、最近邻2倍）。将已目视确认的数字真实位置映射回检测输出，在不改变0.3阈值下测得：

| 真数字 | 原彩图检测最大概率 | 大于0.3的像素数 | 独立原像素裁剪的直识别 |
|---|---:|---:|---|
| 2 | 0.007820934 | 0 | 2 / 0.966 |
| 上方1 | 0.0000031888485 | 0 | 1 / 0.986 |
| 下方1 | 0.0000067055225 | 0 | 1 / 0.994 |

这些位置没有候选框，因而不是框排序、坐标映射或候选平均分过滤误删。单独裁剪能读只说明识别器具有能力，不提供生产流程所缺的通用定位方法。

灰度可恢复2/0.927，但两个1仍漏；原彩图320/640纵向分块仍漏，说明仅避免长图缩小也不足。左右各60黑边可恢复2/0.852，仍没有两个1；左右白边却会把右侧被裁断的正文识别成1/0.841。其他通道、反色、二值、四周补边均未补齐，部分还把图标/箭头条读成字符。原输出中的一处“1”实际来自右侧截断正文框，并非正确定位了所需计数，不能把部分实体碰巧匹配当定位成功。

未采用按已知系列位置裁数字、硬补字或轮询许多变体取想要答案的方案。要修复此类长列，还需要通用的小文字定位方法，并用更多真实面板及无文字图标约束误识别；现有证据不支持把上述常规变换接入正式路径。
