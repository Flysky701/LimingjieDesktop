# 固定模型前处理诊断

本文记录对固定 PP-OCRv5 模型在低清地图数字与系列效果长列上的前处理实验与诊断结论。

## 复现方式

执行以下命令可将各变换变体、检测框与原始 CTC 解码得分输出至 `desktop/ocr/build/reports/preprocessing-diagnosis/`（归档数据见 [preprocessing-diagnosis.tsv](preprocessing-diagnosis.tsv)）：

```powershell
desktop\gradlew.bat -p desktop :ocr:diagnosePreprocessing
```

测试输入包含两个低清地图计数、系列效果面板、四个 1920×1080 地图计数，以及五个同图无文字图标/背景负样本（加号、准星、双剑、箭头条、纯背景）。

## 低清紧凑数字：四周黑边回退

在低清截图 `node-link-20260914.png` 的 `map-link-0` 中，数字紧贴绿色图标与裁剪边缘，常规检测无候选框，整图直接识别得分也低于 `0.5` 阈值：

| 输入 | 整图直接识别（原始得分） | 常规检测 | 四周补 1/4 短边黑边后 `det+rec` |
| --- | --- | --- | --- |
| 低清数字 `5` | `G` / 0.136 | 无框 | **`5` / 0.835** |
| 低清数字 `2` | `2` / 0.873 | 无框 | **`2` / 0.968** |

- 双线性/双三次缩放、灰度化或补白边均未能使低清 `5` 达到 `0.5` 阈值；且无条件对所有输入加黑边会导致高分辨率数字 `2` 的常规检测退化。
- 因此仅在紧凑 ROI（宽高 `32..256`、长宽比 `0.5..2`、非纯色）常规检测与整图直识别均无结果时，才追加一次四周 `min(w,h)/4` 黑边的 `det+rec`。五个无文字负样本在此回退下均保持空输出。

## 系列效果长列：按行角标核验

原 `series-visible` ROI 为 `240×1426` 纵向长条。在整列直接送入检测器时，三处数字位置的检测最大概率均远低于 `0.3` 阈值，但单独裁剪数字区域均可高置信度识别：

| 目标数字 | 整列检测最大概率 | `> 0.3` 像素数 | 独立裁剪直接识别 |
| --- | ---: | ---: | --- |
| `2` | 0.0078 | 0 | `2` / 0.966 |
| 上方 `1` | 0.0000032 | 0 | `1` / 0.986 |
| 下方 `1` | 0.0000067 | 0 | `1` / 0.994 |

单纯灰度化、纵向分块或补边无法在整列上稳定检出全部角标，且补白边易将右侧截断正文误读为数字 `1`。因此在系列面板标题确认后，桌面端改为按已定位的系列行读取图标右下角角标区域，并要求原图与去除图标背景后的字形读出相同数值，从而稳定通过 `series-visible` 评估。
