# 黎明界角色输出 / 辅助 / 配队战斗模型 V2 说明

V2 是本目录的离线战斗审阅模型。打开 `index.html` 可查看角色、评分和配队快照；桌面使用方法见[用户指南](../../docs/USER-GUIDE.md)。重新生成所需的评分表、攻略摘要和数据库见第 17 节。

[数据来源](#2-数据层级) · [评分与配队](#10-主力队生成现在如何使用辅助) · [数据覆盖](#13-当前覆盖率) · [重新生成](#17-输入准备与重新生成)

## V2（2026-08-31）历史修正

V2 针对“模型高分、真实玩家评价明显偏低”的审计结果加入三类关键修正：

1. `action_type=28` 条件档位不再把互斥分支全部按 100% 同时结算；当前先使用保守的条件覆盖近似，并保留门槛元数据，后续可替换为逐角色精确状态机。
2. 友军负面效果进入**净队伍贡献**。其中“初始值的 X%”这类比例型攻击力 / 暴击下降会按比例处理，而不是误当成固定点数。
3. 输出拆为 **1目标 / 2目标 / 3+目标** 三种场景。BOSS 队默认看 1 目标输出，多目标节点才使用对应多目标输出。

另外补齐了攻击循环中的 `2001 / 2002 / ...` SP 技能映射；这类技能经常负责初始化印记、层数或特殊状态，不能继续忽略。

> V2 解决的是“互斥条件全部叠加”等结构性高估，不等于已经精确模拟所有印记增长/消耗过程。像【剑之刻印】【水月】仍属于下一阶段应做的逐角色状态机。

## 1. 目的

本模型用于替换早期审计页中的启发式规则：

```text
用户评分 × 职阶系数 × 技能文本出现次数
```

新版原则是：

1. **真实用户评分只表示角色总体质量**，不再用于推导物理/法术输出。
2. **物理 / 法术类型、站位优先读取游戏数据库事实**。
3. **输出能力从黎明界实际强化配置、面板、行动循环、skill_action 计算**。
4. **辅助能力先计算真实底层量和对标准队伍的预计增益，再转换成 0–100 展示分**。
5. **真正配队优先使用“实际队伍增益”，不把 0–100 展示分直接当百分比**。

## 2. 数据层级

### 2.1 当前入库快照与数据库来源

当前 `data.js.sources` 记录的角色与战斗数据库为 **autopcr-db-builder / 202609021434.db**，版本对应已入库快照。

生成器支持通过 `--database <可读SQLite路径>` 与 `--database-version <版本>` 显式指定数据库。默认缓存位于 `role-team-review/cache/master_cn.db`；`--update-db` 走历史公开源下载分支。早期曾对比以下来源：

- Expugn `master_cn.db`
- `redive.estertion.win/db/redive_cn.db.br`

早期 2026-07 对比记录如下，保留用于来源追溯，不作为当前快照的哈希：

```text

MD5: 561a812e44892ea6ce365b05556a3ac7
SQLite size: 28,973,056 bytes
```

对哈希表名 / 哈希字段名的数据库，生成器通过语义结构解析逻辑表；显式传入可读数据库时读取可读表。

当前库优先提供：

- `atk_type`：物理 / 法术类型

## 4. 面板计算

面板叠加顺序与 AutoPCR `calc_unit_attribute()` 保持一致：

```text
星级基础属性
+ 星级成长属性 × (角色等级 + Rank)
+ Rank 固定属性
+ Rank promotion bonus
+ 六件装备属性
+ 装备强化属性
+ 专武基础属性
+ 专武等级成长属性
```

计算字段包括：

- HP
- 物理攻击
- 魔法攻击
- 物理防御
- 魔法防御
- 物理暴击
- 魔法暴击
- TP 上升
- HP 回复上升
- 吸血
- 命中
- 回避
- 穿透等

### 当前 V2 的面板假设

黎明界强化模板只告诉数据库“装备槽是否装备”，没有逐件装备强化等级。

V2 对已装备物品使用对应 Rank 可查询到的**最高装备强化等级**；高 Rank 无直接记录时沿用最高可用强化档（当前通常为 5）。这一点属于模型假设，后续应使用游戏内实际角色面板截图或战斗数据做一次校验。

羁绊故事属性目前不计入，因为黎明界 NPC 模板没有表达玩家羁绊状态。

当前模板 EX 装备为 0，因此 V2 不额外加入 EX 装备。

## 5. 行动循环

直接读取：

```text
unit_attack_pattern.atk_pattern_1 ~ atk_pattern_20
unit_attack_pattern.loop_start
unit_attack_pattern.loop_end
```

基本动作编码：

```text
1     = 普攻
1001  = 技能1
1002  = 技能2
1003  = 技能3
...
```

例如日和莉：

```text
技能2 → 技能1 → 普攻 → 普攻 → 技能2 → 普攻 → 技能1
loop_start = 3
loop_end   = 7
```

即：

```text
开场：技能2 → 技能1
循环：普攻 → 普攻 → 技能2 → 普攻 → 技能1
```

### 90 秒窗口

V2 按 90 秒战斗窗口计算：

```text
开场序列执行 1 次
+
循环序列重复直到 90 秒
```

动作时间优先使用：

- `unit_data.normal_atk_cast_time`
- `skill_data.skill_cast_time`

这样可以正确处理**只在开场使用一次**的技能。

例如水咲恋的 TP 技能只在开场释放一次。如果只计算稳定循环，会错误得到 TP 辅助 = 0；90 秒完整窗口已经修正这个问题。

## 6. skill_action 当前支持的主要效果

V2 已直接解析数据库动作，不再依赖中文“中幅 / 大幅 / 特大幅”作为主评分来源。

### 伤害

`action_type = 1`

主要伤害公式：

```text
伤害基础值
= action_value_1
 + action_value_2 × 技能等级
 + action_value_3 × 对应攻击力
```

再结合动作频率与暴击期望，得到物理 / 法术 DPS proxy。

### 属性 Buff / Debuff

普通状态 `action_type = 10`：

```text
数值 ≈ action_value_2 + action_value_3 × 技能等级
持续时间 = action_value_4
```

目前识别：

```text
10  物攻↑
11  物攻↓
20  物防↑
21  物防↓
30  魔攻↑
31  魔攻↓
40  魔防↑
41  魔防↓
60  物暴↑
61  物暴↓
70  法暴↑
71  法暴↓
80  TP上升↑
81  TP上升↓
100 物理暴伤↑
101 魔法暴伤↑
102 物理伤害↑
103 魔法伤害↑
```

### 领域

`action_type = 38`

领域数值布局不同于普通 Buff：

```text
数值 = action_value_1 + action_value_2 × 技能等级
持续时间 = action_value_3
范围 = action_value_5
```

领域使用 `target_type = 7` 时表示领域锚点，**不能当成“只影响自身”**。V2 尚未根据五名角色的精确站位逐个计算是否在领域内，因此对友方领域暂使用 0.65 的保守目标覆盖系数。

### 行动速度

`action_type = 8`, `detail = 2`

例如 `1.5` 表示约 1.5 倍行动速度。

### TP 回复

`action_type = 16`

保留真实底层量：

```text
每次 TP 回复
每 90 秒触发次数
平均 TP / 秒
```

### 治疗 / 缓回 / 护盾

已覆盖：

- `action_type = 4`：直接治疗
- `action_type = 48`：缓回 / TP持续回复
- `action_type = 6`：护盾
- `action_type = 72`：物理 / 魔法伤害减免

### 条件动作

V2 不会把条件分支的多条结果同时当 100% 生效：

- 条件分支 `type=53`：未知条件时分支权重 0.5
- 反击 / 受击触发 `type=42`：V2 权重 0.35
- 条件门 `type=28`：读取门槛，并对后续所属档位使用保守覆盖率；`<33 / ≥33 / ≥66 / =99` 不再全部满额叠加

`type=28` 当前仍是保守近似，不是完整层数状态机。它主要用于先消除 V1 最严重的“互斥档位全吃”错误。

## 7. 物理 / 法术输出分如何计算

### 7.1 底层量

先计算角色自身：

```text
普攻频率
技能频率
技能伤害公式
自身平均物攻 / 魔攻 Buff
自身平均暴击 Buff
EX 被动
参考 UB 频率
```

得到：

```text
physicalDpsProxy
magicDpsProxy
oneTargetDpsProxy
twoTargetDpsProxy
threeTargetDpsProxy
pureAoeThreeTargetProxy
```

这些值**完全不使用真实用户评分**。

### 7.2 暴击期望

V2 使用近似：

```text
100 暴击 ≈ 同等级情况下 +5 个百分点暴击率
```

普通暴击伤害按 2 倍处理，因此：

```text
暴击期望伤害倍率 ≈ 1 + min(1, 暴击值 × 0.0005)
```

这是标准化近似，不是完整游戏内部命中 / 等级差暴击公式。

### 7.3 UB

没有敌方受击、己方受击、实际 TP 流等完整战斗状态时，无法精确预测每次 UB 时间。

V2 使用：

```text
参考 UB 间隔 = 18 秒
```

主要用于让拥有高伤 UB 的角色与 TP 辅助获得合理基础权重。

后续接入真实敌人攻击轴后，应替换为完整 TP 时间线模拟。

### 7.4 转成 0–100 展示分

物理 / 法术输出的原始 DPS proxy 不是直接展示。

对全角色计算后，以正值角色的 **P95（95百分位）** 为 100 分参考：

```text
展示分 = min(100, 角色原始值 / P95 × 100)
```

这样极端异常值不会把其他角色全部压到很低。

> 0–100 输出分是同角色池相对分，不代表“每秒造成多少百分比伤害”。

### 7.5 目标数场景

范围攻击在 1 目标场景只命中主目标一次；在 2 / 3 目标场景才增加额外目标贡献。因此同一角色会分别生成：

```text
physicalDamage1Target / 2Target / 3Target
magicDamage1Target / 2Target / 3Target
```

审计页的组队器新增“敌方目标数”上下文。单 BOSS 不再因为角色有高 AOE 上限就直接按多目标峰值评价。

## 8. 辅助评分如何计算

辅助分分两层：

1. **底层真实量 / 预计增益**：真正用于组队。
2. **0–100 展示分**：用于表格筛选和人工审阅。

### 8.1 Buff 覆盖率

对普通重复技能：

```text
覆盖率 = min(1, 持续时间 × 90秒内平均施放频率)
```

开场一次性 Buff 也按 90 秒总窗口计算，因此不会被当成永久覆盖。

### 8.2 目标人数系数

V2：

```text
全队 / 明确多目标 = 1.00
单个队友          = 0.25
范围 / 领域        = 0.65
自身              = 0
```

单体 Buff 并不代表“弱”，只是因为角色级静态评分不知道它会准确给到哪一名主 C；真正五人队模拟以后可以根据站位和目标规则改成精确目标。

### 8.3 物理专属直接增益

底层物理直接贡献：

```text
物攻平均增量 / 标准物理角色物攻
+ 物暴平均增量 × 0.0005
+ 物理伤害提升
```

标准物理角色物攻使用当前可建模角色的物攻中位数。

法术同理。

### 8.3.1 友军负面效果

V2 使用**净增益**而不是只累计正面 Buff：

```text
净物理直接贡献
= 物攻正增量 / 标准物攻
 - 物攻负增量 / 标准物攻
 - 物攻比例下降
 + 暴击 / 伤害类净贡献
```

法术同理。

例如夏日杏奈的技能“除自身以外我方全体魔攻下降初始值的 90%”，在当前标准五人静态模型中先按四名队友占 4/5 份额处理，因此保存为：

```text
allyMagicAttackRateDown = 0.72
```

并使 `magicTeamUplift` 约为 -72%。这仍是“标准五人等份贡献”的近似；完整五人模拟应按四名受影响队友各自的实际输出占比精算。0–100 的“法辅”展示栏仍只展示正向辅助能力；真正组队使用的是有符号净增益。

### 8.4 通辅的拆分

为避免重复计算：

```text
物理直接增益 = P
法术直接增益 = M

物法共有部分 = min(P, M)
物理专属      = max(0, P - 共有部分)
法术专属      = max(0, M - 共有部分)
```

因此同时大量提升物攻和魔攻的角色会主要进入**通辅**，而不是在“物辅 + 法辅 + 通辅”三栏重复记三次。

### 8.5 行动速度

V2 将行动速度平均覆盖转换成行动吞吐增益，并只作用于非 UB 行动部分。

当前参考：

```text
UB 伤害占比参考 = 35%
普通行动占比    = 65%
```

因此：

```text
速度通辅增益 ≈ 平均速度吞吐增量 × 65%
```

### 8.6 TP 辅助

保留原始：

```text
tpPerSecond
```

再用参考 UB 周期转换成通用输出增益：

```text
标准 TP 需求速率 = 1000 / 18 秒

TP输出增益
= min(60%, tpPerSecond / 标准TP需求速率 × 35%)
```

这里的 35% 来自 V2 的 UB 输出占比参考，不是永久常量。

### 8.7 最终通辅底层增益

```text
通辅增益
= 物法共有直接增益
 + 行动速度吞吐增益
 + TP吞吐增益
```

### 8.8 物理队 / 法术队实际预计净增益

```text
物理队净增益 = 物理专属 + 通辅 + 物理队负面代价
法术队净增益 = 法术专属 + 通辅 + 法术队负面代价
```

这两个值保存在：

```text
combatModel.supportImpact.physicalTeamUplift
combatModel.supportImpact.magicTeamUplift
```

它们是组队器真正优先使用的值。

例如当前 V2 抽查：

### 水咲恋

```text
自身物理输出展示分：约 7
通辅展示分：约 47
预计物理队增益：约 +35.9%
预计法术队增益：约 +36.2%
```

她因此会被识别为**低自身输出、强物法通辅**，不会因为输出分低被算法淘汰。

### 情人静流

```text
物辅展示分：约 30
通辅展示分：约 17
预计物理队增益：约 +29.8%
预计法术队增益：约 +12.6%
```

这里的数值是 V2 模型输出，不应解释成游戏中任何队伍必然精确增加相同伤害。

## 9. 辅助 0–100 展示分

展示栏：

- 物辅
- 法辅
- 通辅
- 生存辅助
- 控制
- 物破 / 魔破

均从底层值做 P95 归一化：

```text
score = min(100, raw / P95(raw of all modeled roles) × 100)
```

因此：

- 100 表示当前角色池中接近顶级，而不是“提升100%伤害”。
- 游戏数值膨胀后不需要重新人工规定“大幅=82”。
- 排名随角色池变化，底层真实量仍保留不变。

## 10. 主力队生成现在如何使用辅助

### 10.0 玩家经验 / 系统适配混合评分

根据实战验证，当前战斗模型仍不能完整描述 EX/BOSS 的点名、范围伤害、阵亡时点和阵亡后的连锁崩盘，因此主力队与实时三选一不再让模型分单独主导。

默认使用：

```text
最终评分 = 国服玩家经验分 × 70% + 当前局系统适配分 × 30%
```

两侧都先保持在 0–100 量纲。强度表原始玩家评分是 **1–6 分制**，五位玩家等权平均后除以6换算到0–100；6分必须保留，不能按5分制解析。系统适配由当前目标数、属性配对、预计输出、生存、一号位、治疗/续航和功能完整度计算；低守备下的明显生存风险会在混合后继续做安全折损。

如果某个角色没有真实玩家评分，不会伪造中性分；缺失的玩家权重按评分覆盖率转交系统侧。页面可调整玩家权重，系统权重自动使用剩余比例。

实时三选一对候选本身同样使用玩家评分 / 系统适配的 70/30 混合。系统适配不再默认把候选强塞进一队，而是分别尝试候选作为一队、二队、三队成员的部署方案；一/二/三队系统权重为 `1.00 / 0.35 / 0.20`，取整体系统价值最高的落点。系统侧另加入轻量物理/法术体系一致性分，避免明显的物理核心被无必要地混入法系输出，或反之；坦克、治疗和真正有价值的混合体系不被硬性禁止。

网页主力编成展示最多三支互不重复的五人队，按 **一队优先** 估值：先确定第一队，再用剩余角色生成后续队伍。Kotlin 正式任务的 Boss 默认多队，编组前扫描「有效效果」。机制参考见 [README-ex-mechanics.md](README-ex-mechanics.md)。

对有战斗模型的角色：

```text
直接读取 physicalTeamUplift / magicTeamUplift
```

多个辅助的 V2 组合方式：

```text
combined = Π(1 + 每人增益) - 1
```

保护限制：

```text
单角色正增益最大按 +80% 进入组合
单角色负增益最低保留到 -95%
全队辅助组合最大按 +200%
```

这是为了防止尚未建模的叠加规则导致爆炸值。

对没有数据库战斗模型的角色，才使用旧展示分回退：

```text
(物辅或法辅 + 通辅) / 100 × 0.22
```

页面会明确标记“技能文本回退”。

### 低守备时的生存门槛

实战验证发现，旧版只把“缺可靠一号位”作为 `-7` 的普通功能缺口处理，可能被高输出完全覆盖，导致守备 0～1 时仍推荐没有坦克、没有有效治疗的玻璃炮队伍。

当前组队器增加守备层数相关的生存门槛：

- `守备 0～1`：可靠前排和有效治疗/续航都没有时，视为严重生存失败；纸面输出按存活倍率折损，并额外追加门槛惩罚。
- `守备 0～1`：只有前排或只有治疗时允许使用，但仍对纸面输出做轻度折损。
- `守备 2～3`：同一逻辑保留，但惩罚明显减弱。
- `守备 ≥4`：不再使用低守备生存门槛，并继续对缺少特殊价值的纯坦/纯治疗做降权。

当前有效治疗/续航优先读取 `healing / regeneration / survivalSupport`；可靠前排优先读取 `reliableVanguard + selfSustain`。对于较新、旧战斗库没有站位校准但职阶明确为“掩护者”的角色，会使用保守的职阶 + 自续航回退，避免把新坦克错误当成零生存价值。

页面会显示：

```text
生存锚点：前排/治疗角色
存活输出倍率：xx%
```

这套系数目前属于基于黎明界实战反馈的 V2.1 校准项，后续应继续用难度 5 的真实阵亡/通关结果校准，而不是把它解释为游戏内部伤害公式。

### 破防为什么暂时不直接乘伤害

当前 0–100 物破 / 魔破是**同角色池归一化展示分**，不是实际防御降低百分比。

真实伤害提升还依赖敌人：

```text
敌人原始物防 / 魔防
当前破防值
防御下限 / 游戏伤害公式
```

因此 V2 主力队中破防先作为“功能完整度 / BOSS价值”参与评分，**不把归一化分强行转换为伤害倍率**。

下一步获得 BOSS 实际防御数据后即可改成真实伤害公式。

## 16. 合卡统一与实时三选一模拟

### 16.1 合卡只作为一个角色参与决策

角色目录中的成员投影不再单独进入审计/选人角色池，而是作为合卡主体的识别别名：

```text
1183 / 1184           -> 1807 初音&栞
1204 / 1205 / 1206    -> 1808 禊&美美&镜华
1217 / 1218           -> 1809 秋乃&咲恋
1243 / 1244           -> 1810 安&古蕾娅
1281 / 1282           -> 1811 静流&璃乃
```

数据库本身存在 `180701 / 180801 / 180901 / 181001 / 181101` 战斗主体，因此输出、站位、技能和行动循环都直接使用合卡主体数据，不拼接成员数据。

Android 三选一规划器同样会先做 canonical ID 转换。即使视觉层识别到 `1217` 或 `1218`，最终都会以 `1809 秋乃&咲恋` 进入选人评分。

### 16.2 实时角色选择模拟器

`index.html` 新增“实时角色选择模拟”区域，输入：

```text
已有角色
本次候选（通常3名）
守备层数
敌方伤害类型
主要目标数（1 / 2 / 3+）
同属性伤害倍率
```

名称、正式名、别名、角色 ID、合卡成员 ID 均可用于解析。

对每一名候选，当前网页模拟器会尝试三个部署层：

```text
候选进一队：候选必须在一队，随后计算二队、三队
候选进二队：先保留不含候选的最佳一队，再在剩余池中为候选组二队，随后计算三队
候选进三队：先保留不含候选的一、二队，再在剩余池中为候选组三队

部署系统分 = 一队系统分 × 1.00 + 二队系统分 × 0.35 + 三队系统分 × 0.20
                （按实际存在的队伍权重归一化到 0–100）

最终候选分 = 候选国服玩家评分 × 70% + 最佳部署系统分 × 30%
```

当“已有角色 + 候选”不足 5 人时，候选只能作为一队部分阵容参与评价；二、三队只在能够组成完整五人队时参与。

结果会展示：

- 候选总排序；
- 候选最佳落点（一队 / 二队 / 三队）；
- 一、二、三队系统分；
- 候选所在队的实际配队；
- 同属性人数及当前伤害加成；
- 队伍物理/法术体系；
- 物理/法术体系一致性；
- 一号位；
- 模型辅助净增益；
- 仍缺少的关键功能。

实测时可点击“采用这个角色并加入已有”，页面会把该候选加入已有角色并清空本轮候选，随后继续下一次选择。


这些值在模拟器中可直接修改。
