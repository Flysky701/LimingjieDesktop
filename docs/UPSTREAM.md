# 上游同步与共享修改

共享代码来自 `wbero/limingjie-assistant`，初始移植基线为 `b809b196988b019571caf5679ccf8d7ebb7f072d`。共享源码位于 `android/`；桌面构建的替身、排除与派生清单位于 `desktop/shared/`。

当前共享功能与执行流程合并自 [SatenRuiko10032/limingjie-assistant](https://github.com/SatenRuiko10032/limingjie-assistant) 的 `limingjie-assistant-copy` 分支，目标提交为 `add2d7a9cd96528097153aba5baf8d4f110e45a6`。该分支包含十公会及新增公会阵容修正；其 `main` 分支仍是此前选择性同步的五公会基线。

在此基线上选择性同步编组（`ca221b4`）、事件（`1455963`）和节点（`d9d0ece`）修复，并从 `ae716d4` 补入事件诊断所需的字段与序列化。未引入自动线程预算与 Android 界面重构；共享计算池仍固定为两个计算线程。

## 当前业务基线与共享修改

- **单局完成与结算衔接**：沿用上游结果页识别与结算导航，关闭最终奖励并稳定返回黎明界主页后结束单局。在此基础上修复结算阶段衔接：关闭分数页后若冷却期内再次识别到 `RESULT` 会保持重试，随后识别到宝箱动画、宝箱结果或最终道具页时即切入对应阶段（若漏帧直接看到最终道具页也直接推进），避免卡在 `SCORE_RESULT` 阶段不点击。该修复位于共享会话逻辑，对 Android 和桌面同时生效。
- **桌面分数识别隔离**：桌面端关闭主识别器内联分数 OCR，改为在结果页缓存最后两帧小区域，离开结果页后交由独立 OCR 识别；核对“分数明细”和总分一致后按单局编号补写记录。Android 保持默认内联开关。分数与耗时仅作观察记录，不参与单局完成判断。
- **桌面架构适配**：多设备隔离、同账号租约、存储及生命周期由桌面层管理；游戏参考坐标映射到实际截图，自动执行开放 1920 × 1080 和 1280 × 720 横屏，720p 待实机验证。上游既有的启动时限、战斗等待时限及战败重试问题见 [已知限制与待办](KNOWN_LIMITATIONS.md#待修复与验证问题)。
- **当前客户端兼容性**：接入节点区域回退修复（`0450781`）、新版遗物效果与购买完成模板、角色卡片几何与错误图库修正（`7111b36`、`b468c79` 中的图库计数修正）、购买过渡帧与掉线提示修复（`2fd3a5f`）、仅限真实开局的角色 1088 几何恢复（`02633fc` 中的识别修复）及商店职能名 OCR 有界重读（`db753a8`）。共享识别和会话逻辑对 Android 与桌面同时生效；两端装配均接入真实开局判定，桌面保留独立分数 OCR、直接像素视图、匹配缓存与预编译角色样本。
- **完整功能与流程**：十公会、开局候选池及赠送角色、自定义事件选项、自定义节点路线与预览、选人确认流程、遗物唯一持有与层数证据、开局遗物收据均使用新版共享逻辑。商店流程跟随上游此次重构；已有用户配置继续保留，桌面响应节拍默认值仍为 300 ms。
- **编组、节点与事件修复**：第一层全部战斗在安全编组搜索失败后允许无合格前排的回退队伍，并按实际战斗节点判断楼层；后续楼层规则和失败重试的人数门槛保持原样。节点分离视觉置信度与拓扑分数，弱语义候选不直接获得点击资格，缓存位置在当前帧重新验证，旧帧或生命周期变化撤销点击许可。事件自定义选项跳过不必要的收益估值，正常 OCR 刷新只保留同一事件的计算，重新确认最新画面后才允许点击。上述修复对 Android 与桌面同时生效，桌面原有实时前台、暂停/停止守卫及任务生命周期管理继续保留。
- **识别调度与点击边界**：桌面捕获接入带序号和不可变像素的引用计数帧，使用上游控制线程与两个计算线程。保留桌面预编译角色样本、分数 OCR 隔离和退出清理；点击在实时前台查询之后再次核对暂停/停止许可。分辨率仅在任务启动时检查，动作前复用启动许可，不额外截图；客户端重启的竖屏过渡复用已有捕获帧。
- **数据兼容与分享**：桌面 Room 替身同步数据库迁移及 schema identity，旧遗物持有记录保留，观察次数不冒充层数。桌面策略库一次迁入旧账号刷取条件，将策略、个人评分与所选账号刷取配置放在一次原子保存中，支持上游分享格式、模块预览、并发修改校验和撤销；旧桌面分享码继续可读。设备 worker 从共享数据服务取得启动快照，凭据不进入分享码。
- **界面及 Android 影响**：桌面策略库提供紧凑摘要、启用状态和更多菜单；共享策略编辑器增加可选宽屏分栏，Android 默认保留折叠布局。新版共享业务、数据库迁移和既有结算衔接修复同时作用于 Android；桌面导航、存储权威和设备操作继续由桌面层装配。

## 上游同步步骤

1. 在独立分支对比目标上游提交，保留上游提交历史。
2. 复核已有共享修复与桌面替身；涉及共享业务行为变更时同步评估 Android 端影响。
3. 更新受影响的替身或派生规则，执行 `desktop\gradlew.bat -p desktop check -Pfull`；若上游新增用例失败，优先补齐适配语义。
4. 同步数据库版本、迁移 SQL、schema identity、设备画像与 UI 入口；涉及 Android 的改动使用 Android 工具链验证。
5. 在提交或 PR 中说明变更范围、验证结果与遗留问题。

## 维护边界

- 保持 `upstream-drift.properties` 的 SHA 锁，核对对应替身后才更新摘要。
- 保持动作前分辨率与实时前台校验、同账号租约、DPAPI 凭据加密及原子存储。
- 新增 Android 耦合按保留、注入缝、派生、替身、装配或排除分类更新清单，并通过全档耦合扫描校验。
- `build/generated` 由构建生成，不在桌面层复制分叉共享业务。

历史补丁与替身台账见 [UPSTREAM_PATCHES](archive/desktop/registers/UPSTREAM_PATCHES.md)、[UPSTREAM_SYNC](archive/desktop/registers/UPSTREAM_SYNC.md) 和 [SUBSTITUTES](archive/desktop/registers/SUBSTITUTES.md)。
