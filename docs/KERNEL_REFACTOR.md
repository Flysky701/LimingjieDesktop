# 迷宫事件内核

每个桌面识别会话持有一个 Kotlin/JVM `KernelRuntime`。`LabyrinthKernelBundle` 注册七个 `KernelDomainModule`，各域通过同一契约接收事件、按 `traceId` 重置和返回状态。会话提供识别帧、路线与策略上下文，管理捕获、异步规划、持久化和输入执行。领域模块生成决策和动作许可，执行器在派发时检查许可，并保留会话、前台、分辨率和当前帧的保护。

| 域 | 职责 |
| --- | --- |
| Map | 路线节点、移动确认、到达回执、视口滚动及卡死轻推 |
| Event | 事件目录匹配、规则与估值、选项许可、页面未推进后的拒选和重规划 |
| Battle | 挑战页与战斗编组、战中等待、特别装备、结算推进和败北重试。事件触发的战斗拥有子 encounter |
| RewardTail | 角色、连结印记和遗物选择、奖励动画与角色加入，以及事件或商店打开的自由选角 |
| Shop | 商品策略、购买目标和弹窗身份、刷新确认，以及新商品出现后的计数结转 |
| Settlement | 分数、宝箱、最终道具和返回黎明界主页。主页稳定后产出通关决策 |
| Recovery | 会话失效和渠道弹窗抢占、返回标题的许可与回执，以及动作锁和未知页面超时 |

`KernelDecision.Wait` 表示等待条件满足，`Act` 给出拟执行动作及可选目标和坐标，`NeedEvidence` 带结构化错误并等待新证据或由会话停止，`Complete` 结束当前 encounter，`FinishRun` 给出整局终态。`KernelError` 记录稳定的错误码、来源、详情和类别，类别包括证据、状态、策略、许可、执行和超时。

`KernelEncounterStack` 跟踪当前路线或事件上下文。Map 确认目标页后记录节点到达。事件触发竞技场等战斗时，Battle 在父事件之上压入子 encounter，记录其父 ID，并在观察到战斗之后的页面时退出子 encounter。事件仍可继续发放奖励或进入后续选项。回到地图时关闭该事件上下文。重新导航、路线重置和停止都会清理未闭合的 encounter。

## 启动时加载事件包

桌面端从数据目录下的 `event-packs/` 读取扩展包。`EventPackRepository` 合并内置目录之上的两层扩展。目录层可添加事件、标题别名、标签和选项效果，策略层可提供条件规则和未知事件策略，两层也可在同一个包中提供。仓库按清单顺序、包 ID 和文件名确定加载顺序，隔离无效或冲突的包，并记录规则来源。每次会话启动时读取并冻结目录和策略快照，目录变更在下次启动时生效。

规则按优先级降序和规则 ID 升序取首个命中项。推荐仍需通过当前帧的按钮位置、稳定次数、亮蓝置信度和拒选检查。未知事件默认等待。启用免费选项策略时，按该策略使用已核对的选项文字及按钮证据。`UnknownEventDraftExporter` 可从未知事件记录导出目录草稿，供复核标题、选项和解析出的效果。

## 因果与落盘

同一个 runtime 的 `eventSeq` 持续递增。每次启动生成独立的 `traceId`，派生记录通过 `causeEventSeq` 指向直接原因，并携带相关帧号和场景代。可以沿父指针查看观察、状态归约、决策、许可、派发与回执。输入回执表明执行器返回的结果，节点到达、购买完成和整局通关还分别要求后续页面证据。钩子可否决领域动作，事件选项覆盖还需再次通过按钮门禁。

内存日志保留最近 2,000 条，`causalChain` 返回其中仍保留的链段。启用落盘后，`KernelJournalSink` 按 trace 追加 `events.ndjson`，刷新记录并替换 `snapshot.json`，停止时关闭文件。`KernelJournalReader.verifyAndLoad` 检查记录可解码、trace 一致、序号递增以及快照计数和末尾序号匹配。`LabyrinthDiagnosticsRecorder` 读取绑定会话的内存日志，在直接导出的诊断 ZIP 中写入脱敏的 `kernel/events.ndjson`。

会话启动时将 `traceId` 绑定到 `AppLogger`，停止时清除进程日志的活动绑定。诊断包的 `manifest.json` 保留最近一次会话的标识，事故现场的 JSON 保存采集时的标识，可与同包中的 PNG、内核事件和进程日志对照。参见 [日志与诊断](DEVELOPMENT.md#日志与诊断)。
