# desktop.9 ADB 冷启动修复

日期：2026-10-27。版本：**1.0.18+desktop.9 测试候选版**。以 desktop.8 基础版为起点，仅修复本次 ADB 进程清理问题，待用户测试后发布。

## 现象与原因

MuMu 正常运行且 adb.exe 可用，但助手检测设备时报 `cannot connect to adb daemon at 127.0.0.1:5037` 或 `ADB 通信中断：Connection reset`。

助手在后台服务未启动时调用 `adb start-server`。命令成功退出后，通用清理逻辑仍枚举并结束它的子进程。Windows 上这会误结束刚启动、应长期运行的共享 ADB 服务，随后的设备查询因而失败。本机旧代码的 discovery-only 探测和独立子进程回归用例均复现了该问题。

## 修复

`ProcessAdbExecutor.terminate` 只在所持命令进程仍存活时终止进程树。已退出的命令仅关闭输入输出流，保留共享 ADB 后台服务。超时、取消和关闭执行器时，对仍在运行的命令继续执行原有清理。

未更换模拟器 ADB、未修改端口配置或业务流程。原有 desktop.8 基础包与本地基线标签保留。

## 已完成验证

- 新增“启动命令结束、执行器关闭后后台子进程仍存活”的回归用例：修复前失败，修复后通过。
- `ProcessAdbExecutorTest` 共 11 项通过，无跳过，包括超时清理父子进程和取消命令清理。
- 修复后的生产发现路径在本机成功冷启动 ADB、读取 MuMu 实际端口、登记并发现 `127.0.0.1:16480`（V2309A）；探测结束后 ADB 服务仍运行。
- 已打开的 desktop.8 窗口在服务恢复后重新检测成功，设备列表恢复。该旧窗口使用的程序尚未包含本修复，后续应启动 desktop.9。

本次未登录账号、未启动游戏任务。上述连接排查不能替代基础版的完整用户验收。

## 使用

退出旧助手，将新包解压到独立目录并启动 `LimingjieAssistant.exe`，确认版本为 desktop.9。进入“设备”页进行检测和连接；后续沿用随包单开测试清单。需要沿用数据时，关闭相关助手后复制主数据目录及相邻的 `-run-tabs` 目录，保留原件。
