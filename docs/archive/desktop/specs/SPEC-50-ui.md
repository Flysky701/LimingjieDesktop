# SPEC-50 桌面界面（WS-F）

## 1. 原则与界面设计基线（D-11、D-25、D-37）

### 1.1 核心原则

- **业务能力和行为保持一致，界面按桌面使用方式重新设计。** 助手功能页面均在 Windows 内使用，模拟器只运行游戏，不承载安卓版助手界面。
- 原版 `LabyrinthScreen`、`AccountScreen`、`LabyrinthStrategySettingsScreen`、`LabyrinthOpeningRosterScreen`、`LabyrinthRoleRatingsScreen` 及内部对话框是功能与行为盘点基准，不要求原样嵌入。适合的组件可复用，其余在 `desktop/app/…/ui/` 自有包实现。
- 允许调整页面、信息层级、控件、配置分组、字体、配色、间距和展示文案。每项原功能必须有明确桌面入口；保留业务字段、默认值、合法范围、校验、保存 / 取消、确认步骤、状态和动作语义。数据继续来自上游状态与 ViewModel，操作经 `DesktopAppGraph` 接入原业务入口。
- 不复制或重写识别、决策和协议逻辑，不修改 `android/` 或共享生成源码做美化，不以简化页面为由删减原能力。机器判断使用的错误字符串保持不变，展示层可补充桌面指引。
- MAA 是导航、配置、日志与运行控制的组织参考，不要求复制其外观、品牌资源或增加上游没有的功能。单设备、单任务与 P2 边界沿用 PLAN。
- `ClanBattleScreen` 在基线上游导航未接入，桌面同样不接入；编译和测试要求不变。

### 1.2 轻量原型与功能梳理

大规模实现页面前，先给出一份可查看、可切换主要页面的原型，以黎明界任务页、账号库和策略设置为代表，展示整体布局与主要操作。原型和少量示例图放在 `docs/desktop/design/`；`UI_DESIGN.md` 用简短文字记录页面组织、统一样式与实际反馈。未覆盖的页面沿用同一套样式，不要求一次画齐所有页面和状态组合。

`UI_PARITY.md` 按功能分组记录原功能的桌面去向，重点记容易遗漏或本次改变的入口、配置和确认。无需建立逐字段证据表；具体字段仍以现有源码与业务校验为准，不能因清单简化而删功能。

原型标明示例数据，不连接真实账号或控制游戏；它用于展示形态，不是功能完成证据。交给用户查看后，按已授权原则继续推进，收到反馈就调整；不新增独立 Gate、逐页审批或等待确认的流程，也不把未回复记作确认。后端工作可并行。

### 1.3 默认页面组织

| 页面 | 桌面组织 | 行为约束 |
|---|---|---|
| 黎明界 | 当前账号与任务配置为主；区分刷开局、只读识别与画面自动化；策略 / 编组 / 评分入口可见；反馈邻近任务控制 | 不组合成上游没有的队列，启动条件与互斥不变 |
| 账号库 | 列表与编辑区分栏；宽度不足时列表与详情分步显示 | 新增、编辑、选择、删除确认与登录语义不变 |
| 策略 / 编组 / 评分 | 独立子页或宽对话框；按原字段分组，区分查看和修改 | 不改变默认值、范围、排序含义、保存 / 取消和校验；实际字段以源码为准 |
| 设备 | 设备选择与连接为主，ADB、截图耗时、触控状态放在详情 | 未连接不阻止查看本地页面，相关任务按原前置条件阻断 |
| 设置与环境 | 日常设置与检查分组，每项异常给出下一步 | 不弱化前置检查，不把故障仅藏在日志中 |
| 诊断 | 面板、诊断包、日志与崩溃记录集中展示 | 常规功能不要求用户手动执行命令 |

## 2. 窗口与外壳布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶栏：● MuMu 12 · 127.0.0.1:16384 · 已连接 · 1920×1080 · Raw 85ms · MaaTouch   │
│       当前账号：<别名>（<服务器>）                         任务：运行中 / 空闲   │
├──────────┬───────────────────────────────────────────────┬───────────────────┤
│ 黎明界    │                                               │ 任务日志           │
│ 账号库    │      桌面功能页（共享业务状态与动作）             │ 12:01:02 开始…     │
│ 设备      │                                               │ 12:01:05 识别到…   │
│ 设置与环境 │                                               │ ……                │
│ 诊断      │                                               │ [画面预览（可折叠）] │
├──────────┴───────────────────────────────────────────────┴───────────────────┤
│ 任务栏：<标题> · <状态> · <详情>              [暂停] [继续] [停止]              │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 默认 1280×800，最小 1100×700，记住窗口位置和大小（`settings/desktop.json`）；位置落在当前任何显示器之外时重置到主屏居中。
- 标题：`黎明界助手 <显示版本>`。图标沿用上游应用图标（从 Android 资源转换为 `.ico` / `.png`，登记来源）。
- 页面按可用内容区自适应；优先收起非必要详情或日志预览，再重排表单，主要操作保持可达。仅在复用需要 Android 环境的组件时，以 `BoxWithConstraints` 提供该组件内容区尺寸的 `LocalConfiguration` / `LocalContext`（D-25）；不强制沿用 Android 紧凑排版。
- 字体：`Microsoft YaHei UI`，退回系统默认。不打包字体。
- 主题：Material 3 浅色，允许统一调整桌面配色，保留产品身份。颜色、字号、间距与控件样式集中定义，避免每页各用一套；深色主题仍属 P2。
- 主次操作、选中、悬停、键盘焦点、禁用、加载、警告和错误状态统一；状态同时用文字表达。图标使用可合法复用的现有资源或统一图标集，不随意增加依赖。
- 支持鼠标、滚轮、Tab 和可见焦点；保留明确的确认、取消按钮及其原行为，不新增触发业务的快捷键。长表单可有序滚动，日志和预览不能挤掉任务状态与停止入口。
- 保存中、校验失败、无账号、无设备等状态可辨认；只在原行为允许时切换或编辑，不新增静默保存、隐式默认值或丢弃未保存内容的路径。

## 3. 页面与接线

### 3.1 黎明界（以上游 `LabyrinthScreen` 为功能基准的桌面页面）

回调逐个对照上游 `LabyrinthRoute`：

| 上游回调 | 上游 Android 前置检查 | 桌面前置检查 |
|---|---|---|
| `onStart`（刷开局） | 通知权限 | 无（不需要通知）。直接调用同样的 `start(retreatConfirmed = true, guildIdOverride)` |
| `onStartEntryRecognition` | 申请 MediaProjection | 设备 Ready → 确保截图已启动 → 启动会话 |
| `onStartEntryAutomation`、`onStartAutoRun` | 无障碍已连接，否则弹「需要无障碍权限」 | 设备 Ready 且触控就绪，否则弹「触控服务未就绪」（§5）→ 确保截图已启动 → 启动 |
| `onStop*`、`onCaptcha*`、`onOpenStrategies`、`onSaveSettings`、`onCheckStatus`、`onDismissMessage` | — | 桌面入口调用同一业务动作，参数、前置条件与反馈语义一致 |

「确保截图已启动」对应上游的 `onRequestCapture`：设备未连接时弹窗「请先连接模拟器」，按钮「前往设备页」。
策略保存保留上游 `LabyrinthRoute` 的 `saving` / `message`、防重入、错误处理与取消异常重新抛出语义，布局可调整。必须盘点策略、编组、评分的内部字段、对话框和确认，不能仅接通打开入口就视为完整。

### 3.2 账号库（桌面页面 + 上游 `AccountViewModel`）

列表、表单和对话框可重排；动作接到原 `AccountViewModel`，UI 不另写账号校验、登录或凭据保存逻辑。ViewModel 由 `DesktopAppGraph` 通过 `AccountViewModel.Factory` 创建，退出时 `clear`。顶部显示设备画像来源（SPEC-40 §2）。字段、服务器类型差异、删除确认、保存 / 取消、错误和加载状态纳入功能对照。

### 3.3 设备（桌面新页面）

- 设备列表（自动检测结果 + 手动地址）、连接 / 断开 / 重新检测。
- adb：当前路径和来源、版本、「指定 adb 路径」、「下载 platform-tools」。
- 截图：模式、测速结果（p50 / p95）、「重新测速」（会断开并重连）。
- 触控：MaaTouch / 兼容模式单选（附说明，SPEC-10 §5），当前状态，「测试点击」（仅在前台不是游戏时允许，在屏幕中央点击一次，用于 L1 自测）。
- 已安装的游戏客户端（与上游 `GameClientResolver` 的结果一致）。
- 设备画像快照摘要（不显示 android_id 原文，只显示后 4 位）。

### 3.4 设置与环境（替代上游「设置与权限」）

**环境检查列表**（按桌面信息层级统一设计；每项包含状态、说明、操作按钮）：

| 项 | 通过条件 | 阻断哪些任务 |
|---|---|---|
| 模拟器连接 | 连接状态 Ready | 全部画面任务；协议登录需要设备画像快照 |
| 截图 | 测速成功；p95 ≤ 600 ms，否则显示黄色警告 | 画面任务 |
| 分辨率 | 1920×1080 横屏；其他尺寸显示黄色警告 | 不阻断 |
| 触控 | MaaTouch 就绪（兼容模式显示黄色警告） | 画面自动化（只读识别不受影响） |
| 游戏客户端 | 当前账号所属服务器的客户端已安装 | 画面任务、协议登录 |
| 前台检测 | 最近一次查询成功 | 画面自动化 |
| 屏幕状态 | `Awake` | 画面任务 |
| OCR | `Ready` | 黎明界画面任务 |
| 凭据加密 | DPAPI 自检通过 | 保存或读取账密 |
| 数据目录 | 可写，并显示路径 | 启动即检查 |
| 网络 | 系统代理 / 直连，以及到 SDK 主机的连通性（用户点击「测试」时才检查） | 不阻断 |
| 游戏内设置提醒 | 上游要求的游戏内设置（例如关闭「播放角色加入动画」，以上游文档为准）以清单形式列出，由用户勾选确认 | 不阻断 |

另外包括：网络模式（跟随系统代理 / 直连）、关闭窗口时的行为、国服数据库更新（保留更新行为与结果语义，入口和展示可调整）、数据目录（打开文件夹）、关于（版本、许可证、第三方声明、上游仓库链接）、「停止截图」按钮（对应上游 `onStopCapture`）。

### 3.5 诊断

- 诊断面板：显示 `http://127.0.0.1:<端口>/`，「在浏览器中打开」（D-13；端口被占用时顺延，FB-10）。
- 「导出诊断包」：调用上游面板生成 zip 的同一个入口，保存位置由用户选择；文件名与上游一致。
- 打开日志目录；最近的崩溃日志列表。

## 4. 任务日志与预览

- **任务日志**只记录面向用户的事件，不是 `Log.d` 的原始输出：`AutomationOverlayPresentation` 的状态和详情变化（去重，相同内容不重复记录）、`labyrinthRerollStatusText` 的变化、上游 UI 状态中的消息和错误、设备层事件（连接、断开、重连、测速结果）、任务开始和结束。每行格式为 `HH:mm:ss 文本`，错误用红色。最多保留 2,000 行；「复制全部」「清空」。
- **画面预览**（可折叠，默认折叠）：显示最新帧的缩略图，并叠加 `AutomationOverlayPresentation.boxes`。刷新不超过 2 fps。预览只能**复制**帧数据，不得持有、也不得回收投递给上游消费者的 Bitmap；具体从哪一层取帧由 WS-H 在 THREADING.md 中确定。

## 5. 任务控制（替代通知和悬浮窗）

- 桌面实现上游的 `AutomationOverlayHost`：`show` / `hide` 控制底部任务栏和托盘菜单是否显示任务项。
- 任务栏的显示内容来自 `AutomationOverlayCoordinator` 的当前 presentation，经 P-05 搬出的 `notificationContent()` 生成文案（`:app` 不能访问 `internal`，所以通过 `:shared` 的公开桥接调用）。「暂停 / 继续 / 停止」走协调器的命令入口，与上游通知按钮的行为相同。
- 刷开局（`LabyrinthRerollService` 的替代）运行时，任务栏显示 `labyrinthRerollStatusText`，只提供「停止」。
- 停止、暂停按钮在命令执行期间禁用，避免重复点击。

## 6. 托盘与关闭

- 托盘（Compose `Tray`）：提示文字为当前任务摘要；菜单项为「显示主窗口」「暂停」「继续」「停止」「退出」（后三项按任务状态启用或禁用）。任务结束或出错时发送托盘通知。
- 关闭窗口：
  - 没有任务在运行：直接退出。
  - 有任务在运行：弹窗「任务正在运行」，选项为「最小化到托盘」「停止任务并退出」「取消」，附「记住我的选择」（设置页可修改）。
- 退出流程：走上游的停止路径停止任务，最多等待 10 s → 停止截图 → 结束 MaaTouch → 关闭诊断面板服务和回环服务 → 关闭数据库 → 清除防睡眠状态 → 释放实例锁。超过 10 s 仍未停止时，记录警告并继续退出。

## 7. 首次启动向导

1. 风险告知：沿用上游 README 中的风险与使用说明（原文），并说明桌面版是社区移植；必须勾选「我已阅读并理解」才能继续。
2. 模拟器准备：MuMu 12 / 雷电 9 的推荐设置（1920×1080 横屏、打开 ADB 调试的位置），附「我已完成」。
3. 连接设备：嵌入设备页的检测和连接部分；可以跳过。
4. 完成：说明 dryRun（只读识别）和真实操作的区别。

完成状态保存在 `settings/desktop.json`；设置页可以重新打开向导。

## 8. 对话框与文案

- 删除确认、策略、编组等对话框可重新设计布局、尺寸和展示文案；确认对象、后果、校验、执行条件、保存 / 取消与关闭行为保持一致，不绕过原有确认。
- 展示文案使用统一、清楚的中文，错误说明「发生了什么 / 影响 / 下一步」（AGENTS.md §4）。业务含义不变，任务状态和错误原因不能被美化文案掩盖。
- Android 专属说明在桌面呈现层替换为对应的设备或触控指引，并记录 UI_PARITY。上游源码与机器判断值保持不变；展示适配通过桌面组件、既有替身或已登记的呈现适配完成，不修改共享生成物。

## 9. 简单验证

- 优先复用已有业务和界面测试，只补本次重设计影响到的接线检查；简单布局和样式直接查看结果，不新增测试框架或像素断言。
- 验证典型操作：选择 / 编辑账号；调整配置并保存或取消；启动任务并使用该任务实际支持的暂停 / 继续 / 停止；出现设备未连接等问题时提示清楚。相同的检查不重复执行，已有结果可直接引用。
- 查看主任务页和一个较复杂表单在默认与最小窗口下是否可读、主要操作可达；顺手检查鼠标、滚轮与焦点。保留少量代表截图即可，不要求所有页面、状态和缩放组合截图。真实游戏验证仍按 G6 的实际条件单独记录。
