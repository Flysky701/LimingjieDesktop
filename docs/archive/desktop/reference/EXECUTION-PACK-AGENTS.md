# AGENTS.md —— 桌面版移植：全体会话必须遵守的规则

适用于本仓库内所有 Agent 会话（总指挥与子代理）。冲突时优先级：本文件 > `docs/desktop/PLAN.md` 与 `docs/desktop/specs/` > 你自己的判断。
上游代码事实与方案描述冲突时，以代码事实为准，并在 `docs/desktop/registers/DECISIONS.md` 写明：「方案假设 X 不成立；事实是 Y（文件:行）；因此做 Z」。
此规则用于核实功能、接口与行为，不把原安卓布局当成桌面必须沿用的约束；桌面呈现以用户授权的 D-37 与新版 SPEC-50 为准。

## 1. 范围纪律

- 核心原则：**业务能力和行为保持一致，界面按桌面使用方式重新设计。** 以 MAA 的操作组织方式为参考，形成完整、清晰、统一的黎明界桌面助手；用户在 Windows 内完成配置、启动、监控与停止，模拟器只运行游戏，不需要安装或操作安卓版助手。
- 业务层继续共享上游识别、决策、阈值、等待、路线、评分、策略、校验与任务逻辑，不借界面调整改变这些行为。作为业务分支依据的错误字符串、状态和协议字段也不得改动。
- 桌面呈现层允许重新实现页面、重排信息与配置分组、调整控件、对话框、字体、配色、间距和展示文案；保留全部业务输入、取值范围、默认值、保存语义、确认步骤与反馈含义。不得因美化删减功能、弱化确认或新增业务行为，逐项登记到 `UI_PARITY.md`。
- 美化实现位于 `desktop/app/…/ui/`；可复用适合桌面的上游组件，但“页面能编译”不等于必须原样展示。不为美化修改 `android/` 或生成的共享源码。
- 桌面侧只写这些：框架垫片（shim）、同名替身（substitute）、平台适配器、装配根、桌面 UI、打包和 CI。
- PLAN.md 范围外的功能不做。P2 清单只有在全部 P0/P1 Gate 通过后才可以开始。

界面开发先给出主要页面原型和简短功能清单，再实现桌面页面；不新增独立验收关卡，不要求逐字段列证据或逐页批准。授权内的布局和视觉细节直接推进，原型供用户查看，实际反馈如实记录；后端准备可并行。

## 2. 上游代码（`android/`）修改规则

只允许以下两类，每一处都要登记到 `registers/UPSTREAM_PATCHES.md`（文件、类别、理由、Android 行为影响 = 无）：

- **(a) 纯搬移**：把 Android 专属文件里的纯 Kotlin 声明原样移到同一包的新文件。不改名，不改签名、可见性和逻辑。
- **(b) 注入缝**：给构造函数或函数加一个带默认值的参数，默认值等于原行为。

禁止：改上游逻辑、阈值、文案或公共签名；删除上游代码；格式化上游文件；在上游代码里加桌面分支（如 `if (isDesktop)`）；改 `android/` 的构建脚本（除非 Android 构建因 (a)(b) 失败，且只做最小修复）。
每次改动上游文件后，Android 工程必须仍能编译，单测必须仍然通过（本地无 Android SDK 时由 CI 验证）。

## 3. 反防御性编程（重点）

本项目要求严谨。严谨指不变式清晰、失败可见，不是到处兜底。

**要做**

- 用类型表达不变式（非空类型、sealed 结果、value class）。违反不变式时用 `require` / `check` / `error` 立即失败，消息写清上下文。
- 可预期的失败复用上游已有的结果类型，例如 `AutomationBackendResult.Rejected(reason)`、`ShellCommandResult`、`ChannelPromptGate.Refused`。
- 外部输入（ADB 输出、网络响应、文件内容、用户输入）在边界处一次性解析成强类型，进入内部后不再重复校验。

**不要做**

- 不在内部调用链上做“以防万一”的 null 检查、范围检查或空集合检查。
- 不写“catch 后返回默认值 / 空列表 / false 然后继续跑”。不写空 catch。不 catch `Throwable`（顶层崩溃处理器除外）。`CancellationException` 必须重新抛出。
- 不加未登记的重试、回退、放宽超时或降级路径。确实需要时，先登记到 `registers/FALLBACKS.md`：触发条件、次数上限、用户可见信号、对应的 EDGE_CASES 编号。
- 不为假想的需求加配置项、开关、抽象层、插件机制，或给接口写多个实现。
- 不顺手重构或改名业务代码，也不刷屏式加日志；按 SPEC-50 重组桌面呈现代码属于本次授权范围。

**try/catch 只能出现在以下边界**：子进程 / ADB I/O；网络；文件系统；原生库加载与推理（ONNX Runtime、SQLite、JNA）；外部数据解码；UI 事件处理的最外层；协程作用域最外层的 `CoroutineExceptionHandler`。
捕获后只有两种处理：转换成该边界的类型化结果，或者带上下文重新抛出。

**自检**：某模块代码量超过 SPEC 估算的 1.5 倍时，停下来检查是否写了防御性代码或重复代码。

## 4. 错误与用户可见性

- 任何导致任务停止的错误，UI 都必须写清三件事：发生了什么；影响（任务已停止 / 已暂停）；用户下一步能做什么。用中文，措辞风格与上游一致。
- 不自动续跑中断的自动化任务（与上游一致：出现异常就停下，交给人）。设备连接可以自动重连，任务不自动续跑。

## 5. 安全

- 永远不提交、不打印：账号、密码、access_key、token、cookie、验证码结果、未脱敏的网络报文、含个人信息的截图。
- 测试只用 fixtures 和假实现。
- **实机限制**：除非用户明确许可（环境变量 `LIVE_GAME_ACTIONS_ALLOWED=1`，或用户书面同意），对游戏客户端只能跑 dryRun 会话（只截图识别，不派发点击）。对非游戏应用（如系统设置）可以做输入、启动、强制停止的自测。
- 所有本地服务只绑定 `127.0.0.1`。

## 6. 测试

- 上游 JVM 单测必须在桌面构建下全部运行并通过；每个被排除的测试都要登记理由。
- 每个桌面适配器都要有单测：解析器使用真实格式样本（fixtures），进程和网络使用假实现；不 mock 上游纯逻辑。
- `docs/desktop/EDGE_CASES.md` 每一条都要映射到以下之一：测试名 / 实机清单项 / N/A（附理由）。
- 不写只断言“没有抛异常”的测试。
- 界面改版保持轻量验证：复用已有检查，只验证受影响的典型流程；不为美化新增测试框架、独立 Gate、逐字段证据或完整截图矩阵。一次有效验证可被多处引用，不为填表重复执行。

## 7. Git 与协作

- 主干分支：`desktop/main`。子代理使用独立 worktree 和分支 `desktop/ws-<id>`，只改自己拥有的路径（见 `docs/desktop/WORKSTREAMS.md`）。
- 小步提交，提交信息格式：`<ws-id>: <动作> <对象>`。
- 共享文件只由总指挥修改：`desktop/settings.gradle.kts`、`desktop/gradle/libs.versions.toml`、`desktop/app/**/DesktopAppGraph.kt`、`docs/desktop/registers/DECISIONS.md`。子代理需要改时，在报告里提出变更请求。完整的路径归属和登记表编辑规则见 `docs/desktop/WORKSTREAMS.md` §2。
- 不推送到上游仓库，不向 `wbero/limingjie-assistant` 提 PR。

- 上游采用 CC BY-NC-SA 4.0。桌面版作为衍生作品沿用同一许可，并保留署名和第三方声明（包括 LandosolRoster 的 GPL-3.0 声明）。
- 新引入的依赖、二进制或模型都要登记到 `THIRD_PARTY_NOTICES`：许可证、来源 URL、版本、SHA-256。只允许 Apache-2.0 / MIT / BSD / EPL / LGPL（动态链接）这类许可，禁止新引入 GPL 类依赖。

## 9. 必须停下来问用户的情况（除此之外一律自主决策）

1. 需要真实账号、密码、验证码，或者需要在游戏里执行非 dryRun 操作。
2. 不改上游决策逻辑或阈值，桌面版就无法工作（附证据和两种方案）。
3. 发现会阻止分发的许可冲突。
4. 同一根因连续修复 3 次，仍未通过同一个 Gate（附诊断）。
5. 缺少必要环境，且无法自行安装（例如没有网络，拉不到依赖）。

提问时一次列出所有问题，给出推荐选项及影响，然后先继续做不受影响的工作。

## 10. 任务完成定义

代码 + 测试 + 相关登记（DECISIONS / FALLBACKS / UPSTREAM_PATCHES / SUBSTITUTES / UI_PARITY）+ 对应 Gate 通过 + 更新 `registers/PROGRESS.md`。原型完成、界面接通与实机验证分别记录，不互相替代。
