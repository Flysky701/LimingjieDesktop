日期：2026-10-25。状态：UX-0 / UX-1 完成，等待用户确认后进入 UX-2。

打开 [交互设计稿](../design/ux-review.html)，顶部可切换五类关键页，右上角切换浅深色。全部文件离线可打开；HTML 通过相对路径读取仓库现有头像，不需要连接服务。

本稿沿用包中 #6952d5 主色、76px 窄导航和三栏结构，调整了以下内容以符合真实字段：

- 任务保留全部五项，补上参考 PNG 未列出的“执行入口流程”；刷开局标“网络”，读取开局标“只读 · 登录读取”，避免与不登录的画面分析混淆。
- 面板标“已加入角色”，不把 joinedCharacters 误称为当前上阵队伍。
- 路线节点只显示数量和当前位置，不凭末尾位置标 Boss。
- 不把遗物 observationCount 解释成持有数量；折叠用“+N”。
- 暂不展示平均用时，直到桌面运行记录有可靠数据；首次使用明确显示尚无记录。
- 游戏前台显示“上次检查”，重查为主动操作；计时不使用 checkpoint.updatedAt 代替开始时间。
- 停止建议只解释现有结果，不修改标题误判、OCR、策略和任务时序。

## 可操作的预览范围

主题切换、五个任务选择、完整配置抽屉及 Esc 返回、窄栏标签、日志过滤/搜索、Ctrl+F、F6 暂停示意、F7 停止示意、原始原因展开、角色搜索/属性/定位/排序/已修改筛选、↑↓ 移动、Enter 应用评分和恢复原评分均可演示。

评分必须输入 0–100 的整数，空输入不提交；只有“恢复原评分”删除个人覆盖。此页修改先留在示例草稿，返回策略再保存。它没有调用真实 `onScoreChange`，正式版对照测试仍需在 UX-5 完成。

账号、设备、记录、设置、编组、原版评分入口当前打开用途说明抽屉。策略滑杆和保存用于表达外观，不是上游表单的重新实现。复制按钮仅复制本稿示例文本；F5 不启动程序或任务。

## 实现前已识别的约束

详见 [字段与状态盘点](INVENTORY.md)。主要有三点：

1. 批量 checkpoint 没有开始时间，数据库也没有现成状态流；需在桌面侧补缓存和运行记录，不能假定读字段就能实现。
2. 策略函数自己创建 Dialog，不提供布局 modifier；原生评分入口又嵌套在该函数内部。880dp 外层约束与原生评分的入口需要先验证桌面方案，不能通过改 Android 或复制表单解决。
3. “已有账号和设备最多 3 次点击启动”还依赖上游目标草稿与启动确认语义。当前只是入口设计，正式接线后再实测计数，不提前宣称达标。

## 本次验证与后续阶段

`tools/preview_ux_review.cjs` 用项目目录生成 24 名目录样例，并以 Edge / Playwright 渲染。当前结果：20 组布局（五页 × 两主题 × 两窗口），无页面横向溢出、无缺失头像、底栏可见；代表性交互通过，生成 14 张截图。机器可读结果见 [preview-check.json](../evidence/ux/design/preview-check.json)。已人工查看五类关键页及窄窗口代表图，调整了首屏配置按钮和评分表格密度。

后续按包内 UX-2 → UX-3/4/5 → UX-6 实现和验证；这里没有新增正式程序收集器、存储、通知、托盘、图标依赖或版本。未运行 Kotlin 全量测试、实机性能和发包流程，因为当前仅修改文档与 HTML 原型。
