## 1. 体验目标

1. **打开时**：一眼知道能不能开始、还差什么、该点哪里。
2. **运行时**：一眼看懂正在做什么、进度多少、有没有异常。
3. **停下时**：知道为什么停、下一步该做什么。

## 2. 现状问题（总指挥已对照 `evidence/ui` 截图和源码核实）

| # | 问题 | 依据 |
|---|---|---|
| P1 | 存在两套视觉风格：桌面自有页是白卡片；复用的上游页像手机 M3 表单（灰紫底色、通栏滑杆、超大按钮，角色评分一屏只显示 5 人） | 截图 05、06、17 |
| P2 | 主流程跳转太多：账号页选账号 → 设备页连接 → 任务页 → “配置目标与执行”弹窗 → 第 1 步登录读取 → 第 2 步填目标 → 开始。1280×800 下，“配置目标与执行”按钮只露出一半 | 截图 03、17 |
| P3 | 总览页内容和任务页重复，价值低；右侧日志栏空白且没有空状态提示；画面预览默认折叠 | 截图 02 |
| P4 | 运行时只有文字日志和一个 `progress` 字符串。上游已有的结构化状态都没有展示，包括目标进度、阶段、路线进度、队伍、遗物和决策 | 见 §4.2 字段表 |
| P5 | 导航图标是文字符号（◆ ▶ ▤）；状态只靠文字区分，没有颜色或图标层级 | 截图 02 |
| P6 | 停止或阻断原因直接显示内部文案或枚举，没有告诉用户下一步怎么做 | `LabyrinthBatchHaltReason` |
| P7 | 截图里的中文发虚。截图本身可能被缩放过，需要在 100%、125%、150% 缩放下实机确认 | 截图 |

**关键事实（决定了 P1 的修法）**：`android/.../ui/labyrinth/*.kt` 里没有任何硬编码颜色（`Color(0x` 和 `Color.Xxx` 都是 0 处），全部使用 `MaterialTheme.colorScheme` 和 `typography`（bodySmall 用了 58 次）。而 `DesktopApp.kt` 目前只设置了 `primary` 和 `primaryContainer`，其余颜色都是 M3 默认值，这正是灰紫底色的来源。**把桌面主题补全（完整的 ColorScheme、Typography、Shapes），不改上游一行代码，就能统一大部分观感，并让深色模式覆盖上游页面。** 主题改不到的组件细节（例如滑杆的刻度点）接受现状。

## 3. 信息架构

**导航**：共 6 项，分别是：
- **运行**：默认首页，取代原来的“总览”和“黎明界任务”；
- **账号**；
- **策略**：包含编组和角色评分；
- **设备**；
- **记录**：新增，包含运行记录、日志与诊断；
- **设置**。

导航用“图标 + 小字”的窄栏，宽度约 76dp。

**顶栏**
- **设备芯片**：显示状态点、名称、地址、分辨率和触控模式。点开后可以快速重连、断开或进入设备页。
- **账号芯片**：下拉切换当前账号。任务忙碌时禁用，并写明原因。
- **运行状态胶囊**和**深浅色切换**。

**底栏**（始终可见）
- 左侧：一句话状态加副信息。
- 右侧：开始、暂停/继续、停止三个按钮，附快捷键提示。
- 开始按钮被禁用时，要在旁边显示“还差：<就绪检查中第一条未通过项>”，点击后跳到对应位置。
- 不支持暂停的模式（例如刷开局，与上游一致），隐藏暂停按钮，不要只是置灰。

## 4. 运行台（核心，参考稿见 `design/run-console-*.png`）

参考稿表达的是布局、层级和密度，不要求像素级一致。稿中的数据是示例；实现时只能用真实字段，没有对应字段就不显示。

### 4.1 布局与响应式

- 窗口宽 ≥ 1280：三栏。左栏 288，中栏自适应，右栏 340，间距 14。
- 宽度 1100–1279：右栏改为“画面 / 日志”两个标签页；中栏保持不变。
- 高度到 700 时：各卡片内部滚动，底栏始终可见。

### 4.2 内容与数据来源（只读订阅现有 StateFlow）

| 区块 | 字段来源 | 规则 |
|---|---|---|
| 就绪检查 | 见 §4.3 | 只读，不新增轮询 |
| 任务选择 | 现有全部入口，一个都不能少：批量自动执行、刷开局、读取当前开局、只读识别、执行入口流程 | 每项写一句说明，并明确标出“只读 / 会点击” |
| 配置摘要 | `LabyrinthUiState`（难度、目标数、首轮复用等），以及策略的已修改项数 | “编辑完整配置”打开上游 `LabyrinthScreen`，**完整复用**。形式从居中弹窗改为右侧大抽屉或带返回的全屏页 |
| 头部 | `checkpoint.activeGoalIndex/goals`、`currentGuildId`、`startedAtMillis` | 计时器单独按 1Hz 刷新 |
| 阶段条 | `LabyrinthBatchStage`：REROLLING 刷开局 → INVALIDATING_OLD_CLIENT_SESSION 重置会话 → RUNNING_LABYRINTH 执行中 → RECORDING_RESULT 记录结果 | PAUSED、FAILED、COMPLETED 时整条变色并附说明。刷开局和单次识别使用各自的状态，不要套用批量阶段 |
| 区域进度 | `routeProgress`（currentArea、visitedCount、routeNodeCount、nextNodeLabel、complete）；`combatContext`（NORMAL/EX/BOSS、teamIndex） | 节点条只按数量绘制，不臆造节点类型。只有字段里明确有 BOSS 信息时，才标出 Boss |
| 当前队伍 / 遗物 | `joinedCharacters`（使用已有头像资源）、`observedRelics` | 数量太多时折叠成“+N” |
| 批量目标 | `checkpoint.goals`（每个目标的 completedCount 与目标次数）、`runsStarted`、`abnormalRuns` | “平均每次用时”来自 §5 的运行记录；数据不足时不显示 |
| 最近决策 | `roleRewardChoiceDecision`、`eventChoiceDecision`、`battleTeamRecommendation` 或其 `UnavailableReason` | 只展示字段里已有的内容，不自行推断理由 |
| 实时画面 | 现有预览（≤2fps，独立像素副本和框）；`lastResult` 的页面状态与置信度；`frameCount`、`actionCount`、`lastActionLabel` | 运行时默认展开，空闲时折叠。**帧率上限不变** |
| 日志 | `UserLog` | 见 §4.4 |

**空闲时的中栏**：显示“上次运行摘要”（来自运行记录）和一句开始提示，不能留白。

### 4.3 就绪检查

| 项目 | 数据来源 | 何时刷新 | 未通过时 |
|---|---|---|---|
| 模拟器已连接 | `device.state` | 实时 | 一键重连 / 去设备页 |
| 分辨率与触控 | 现有设备画像和屏幕检查结果 | 连接时 | 显示实际值和支持范围 |
| 游戏在前台 | 现有前台查询 | 仅在用户点“重新检查”和点击开始前 | 提示打开游戏 |
| 账号凭据 | `accounts.uiState` | 实时 | 去账号页 |
| 国服数据库 | 现有数据库状态 | 实时 | 去设置更新 |
| 识别模型 | 现有 OCR 加载状态 | 实时 | 显示加载中或失败原因 |
| 关闭“播放角色加入动画” | 无法检测，由用户勾选确认 | 版本变化后重新提示 | 保持警告色 |

- **只读**：不得触发触控、登录或下载，不新增 adb 轮询，只复用 Graph 现有的检查函数。
- 就绪检查只是提示，最终裁决仍是 Graph 的启动前检查。两者结论不一致时以 Graph 为准，把差异写进日志，并在 PROGRESS 中登记。

### 4.4 日志

- `UserLogLine` 目前只有 `time/text/error` 三个字段，并且会直接丢弃连续重复的行。本轮改为：
  - 新增 `kind` 字段，取值为 关键 / 普通 / 警告 / 错误，由**桌面代码在调用处显式指定**；
  - 连续重复的行改为累计显示“×N”。
- 不得用正则去猜文案的级别。上游转发来的文本统一归为“普通”，原有 `error=true` 的行归为“错误”。
- 支持三种过滤（关键 / 全部 / 警告与错误）和搜索（Ctrl+F）。
- 自动滚动：用户往上翻时暂停滚动，并显示“回到最新”。
- 支持复制所选行或全部行。上限 2000 条保持不变。

## 5. 记录页（新增）

**运行记录**
- 字段：开始时间、账号别名、任务类型、目标、结果、耗时、停止原因（含原文）。
- 存储：桌面数据目录下的 `runs.jsonl`。只追加写入，单行原子写；遇到损坏行跳过并提示；保留最近 5000 条或 180 天。
- 采集方式：在桌面层观察 checkpoint 和终态的变化（`LabyrinthRunOutcome`、`HaltReason`、刷开局结果），**不在上游加任何钩子**。
- 进程异常退出后，下次启动时把未结束的记录补记为“未正常结束”。
- 不记录凭据、UID 或截图。

**图表**：近 14 天每日通关次数、平均每次用时。用 Compose Canvas 自己画，不引入图表库。

**日志与诊断**：原页面整体迁入，`/logs.zip` 入口保持不变。

## 6. 其他页面与行为

### 6.1 页面

- **策略**：上游 `LabyrinthStrategySettingsScreen` 的草稿和校验都在组件内部，**只允许改外层**：内容区最大宽度约 880dp 并居中，底部保存条固定，套用新主题。不要复制上游表单代码；需要它暴露滚动状态才能实现的分节锚点不做。
- **角色评分**：上游接口是无状态的（`scores`、`loadCatalog`、`onScoreChange(id, Int?)`、`onClose`），**允许做桌面原生版**：
  - 表格或网格视图，列出头像、名称、属性、定位、ID、原评分、我的评分；我的评分可以直接输入；
  - 支持“仅看已修改”、按属性和定位筛选、排序，键盘 ↑↓ 移动和直接输入；
  - 评分范围 0–100，`null` 表示恢复原评分，校验和提示文字都与上游完全一致；
  - 在设置中提供“使用原版表单”开关，可随时切回上游页面；
  - 写单测：同一组操作在桌面版上产生的 `onScoreChange` 调用序列，必须符合上游代码表达的语义。
- **开局编组**：内部有草稿校验，只做主题和外层调整。
- **账号**：列表加状态徽标（当前、缺凭据、UID 未填），并与顶栏的账号芯片联动。
- **设备**：检测到的模拟器以列表展示，可一键连接；手动地址和 ADB 路径收进“高级”。如果测速已有数值结果，用小条形图展示 p50/p95。
- **设置**：分组，左侧放目录。新增三项：主题（浅色 / 深色 / 跟随系统）、字号（标准 / 大）、通知（运行完成、异常停止、需要人工验证码时发 Windows 通知，可选提示音）。
- **首次向导**：三步，依次是风险说明（原文）→ 连接模拟器（自动检测）→ 添加账号。每步都可以跳过；完成后进入运行台，并展示就绪检查。

### 6.2 行为细节

- **快捷键**（只在窗口内生效，不注册全局热键）：F5 开始，F6 暂停/继续，F7 停止，Esc 关闭抽屉或对话框，Ctrl+F 搜索日志。
- **停止原因说明表**：`docs/desktop/ux/STOP_REASONS.md` 的每一行写清“枚举或来源 → 标题 / 原因 / 建议 / 跳转按钮”，覆盖 `LabyrinthBatchHaltReason` 的全部 8 个值、识别会话的停止消息和启动 `Blocked` 的原因。
  - 原文必须保留，放在可展开、可复制的“详情”里。
  - 例：战斗失败页且没有战斗上下文时停止，建议写“可能停在了标题画面，请先进入游戏主界面再开始”。这只是文案，判定逻辑不变。
- **人工验证码**：出现 captcha 状态时，任务栏图标闪烁并发 Windows 通知。
- **托盘**：图标随状态变化（空闲 / 运行 / 异常），提示文字显示当前进度。菜单提供：显示窗口、暂停、停止、退出。
- **窗口记忆**：记住窗口位置和大小，以及上次所在页面、右栏折叠状态。显示器被拔掉后，窗口回到主屏。
- **禁用必须说明原因**：任务忙碌时禁用的控件，要在悬停提示或行内文字中说明原因，不能只置灰。
- **空状态**：每个列表和面板都要有空状态文案，并给出一个“下一步”按钮。

## 7. 设计系统

- **统一来源**：所有设计变量集中在一个文件 `ui/theme/DesktopTheme.kt`，内容包括：
  - 浅色和深色两套 ColorScheme，主色沿用 #6952d5，**要填满 M3 的全部颜色角色**，包括 surface、surfaceContainer* 系列、secondaryContainer、outline/outlineVariant 等；
  - 语义色：ok、warn、err、info；
  - 间距 4 / 8 / 12 / 16 / 24；圆角 8 / 10 / 14；
  - 字号层级：bodySmall 不小于 12.5sp，正文 13–14sp，标题 16 / 18 / 22。
- **图标**：使用约 20 个 Material Symbols Rounded 的 SVG（Apache-2.0）作为资源，并更新 THIRD_PARTY_NOTICES。不引入 icons-extended（体积太大）。
- **字体**：Microsoft YaHei UI。在 100%、125%、150% 缩放下截取文字局部对比。如果发虚，评估 Compose Desktop 的字体光栅化设置（次像素抗锯齿、hinting），用前后对比图决定是否采用。
- **数字**：计时和计数使用等宽数字。
- **动效**：最多 150ms 的淡入淡出；空闲时不能有持续动画。
- **状态表达**：颜色只做辅助，必须同时配文字或图标，照顾色弱用户。正文对比度 ≥ 4.5:1。

## 8. 性能与线程约束

- UI 只读订阅已有的 StateFlow，派生逻辑放在桌面 presenter 中，不阻塞 UI 线程。除了用户主动点击，UI 不得调用会产生 I/O 的业务方法。
- 运行台的重组频率限制在 4Hz 以内（使用 conflate 或 sample），计时器单独以 1Hz 刷新。预览帧率上限保持 2fps。
- 新增的协程和收集器都要登记到 THREADING.md；现有的退出资源检查（自有协程和线程归零）必须仍然通过。
- **性能回归**：打开新运行台并展开预览，在 MuMu 上用只读识别重跑 10 分钟 L1 采集，满足以下条件：
  - 帧间隔 p50/p95 与上一轮（301/302ms）相比，劣化不超过 5%；
  - 记录窗口可见且空闲时的 CPU 占用，目标 ≤ 2%；
  - 记录 UI 卡顿帧（单帧超过 100ms）的数量。

## 10. 验收

1. **`android/`、`desktop/ocr/` 零改动**：`git diff --stat bf1bad8 -- android desktop/ocr` 必须为空。`desktop/device/` 只允许改动与界面展示相关的只读接口；若有改动，在 PROGRESS 中逐项说明。
