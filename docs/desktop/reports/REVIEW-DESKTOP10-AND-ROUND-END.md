# V10 收益、托盘遗漏与当局结束核查

日期：2026-10-27。核查基于 desktop.10 源码 adbbe74；用户实际运行和本次结束日志来自 desktop.9。按用户要求分为三个并行对话处理，未操作正在运行的游戏或改写既有历史。

## 判断与优先级

1. **优先修正结算收尾。** 两台设备都识别到了结果页，随后因找不到下一节点异常停止；没有完成正常通关记账。该问题与 V10 预览改动无关。
2. **恢复遗漏的托盘成果。** 已恢复到源码，4 项托盘定向检查通过；原有 V10 候选 ZIP 尚未重新打包。
3. **保留 V10，但暂缓继续扩展性能优化。** 看日志、折叠或隐藏窗口时，停止无用预览有价值；持续展开画面时主要减少一次小数组复制，属于边际收益。它不是必须立即升级的核心修复，也未证明能显著降低此前约 2 GiB 的整机采样占用。

## V10 证据与限制

独立探针使用项目既有 480×270 商店图片放大为 1920×1080，重复测量图片处理阶段；没有使用真实账号或控制模拟器。该合成图片不代表全部实际游戏画面的压缩复杂度。

1080p 情形中，局部 CPU 时间中位数：预览编码约 47.7 ms/帧、解码约 22.4 ms/帧、原始像素副本约 1.0 ms/帧。显示画面时移除的 UI 副本约 1.98 MiB/帧、0.26 ms/帧。以上不是整机 V9/V10 对照，不包含所有线程、原生内存或游戏负载，不能据此承诺 CPU 百分比或常驻内存降幅。

后台设备在 V9 已不传预览；V10 只进一步省去它的预览像素副本。空闲设备若没有持续截图，也没有持续副本可省，因此双连接不能简单按双倍收益计算。

另有体验边界：停止截图后隐藏预览会清掉旧画面，恢复时可能需要手动重新展开；运行中的识别不受影响。后续发版前应明确保留最后一帧还是主动刷新，避免以微小常驻内存收益换取体验退化。

探针数据与完整审计位于本机 `.tools/v10-audit/`。

## 托盘恢复范围

遗漏的成果位于 `origin/codex/fix-tray-chinese-font`（tip f07a85e），包含 950e1d6 至 0c658cb 的中文字体、主题、DPI 定位、全菜单配色、圆角半透明等修改。这些提交没有进入 desktop.8–10 的兼容分支，不能归因于 V10 删除了托盘代码。

原样恢复 `DesktopTray.kt` 与原分支测试，在 `Main.kt` 当前窗口主题中接回 `DesktopTray`；保留 V10 的窗口可见性接线、ADB 与共享会话逻辑。定位与主题测试共 4 项通过，深浅主题离线渲染已检查。真实托盘的失焦/Esc、多屏定位、隐藏主窗口后的可用性仍待新包实机确认。

本次不改版本、不覆盖旧包、不发布。源码恢复不代表已经安装到用户正在运行的程序。
