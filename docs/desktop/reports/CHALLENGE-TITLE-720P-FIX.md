# 720p 挑战页难度后缀识别修复

## 证据与原因

用户调试包 `limingjie-debug-20261026-004411.zip` 的实际游戏截图为 1280×720；环境中的 720×1280 是设备方向读数。画面明确显示“战斗格子（普通）”。历史记录的 40 条挑战页样本，普通后缀分数均为 0.7626681788、极难均为 0.4961919062；进入挑战页后等待约 10 秒，因未满足原有最低分 0.78 而停止。

难度由两个固定后缀模板判定，不依赖标题 OCR。1080p 模板为 135×60，720p 对应区域为 90×40。原匹配器将大模板采样点向下取整映射到小图，却仍使用原尺寸模板的像素梯度，导致短文字的边缘与采样相位不一致。页面标题和挑战按钮本身已可靠识别。

调试包 `latest.jpg` 对应 frameVersion 118，状态记录标记 stale、晚于图像约 299ms，不能称为首次停止时的原始帧。JPEG 回放分数与历史原帧有小差异；历史后缀分数稳定一致，截图回放仍复现同一拒绝条件。

## 修改范围

- 仅在普通／极难后缀的目标区域小于原模板时，先对模板作双线性缩小，再交给原匹配器。按模板与尺寸缓存结果，避免每帧重新生成。
- 原尺寸及更大区域继续沿用原路径；其他锚点、通用匹配器、分类门槛（0.78）、差值门槛（0.10）和未确认时等待／超时停止的逻辑均保持不变。
- 上游共享文件：`LabyrinthEntryFrameProcessor.kt` 新增两种后缀的定向处理；新增 `ChallengeSuffixTemplates.kt`。这是本次真实识别故障修复，桌面和 Android 共享源均可使用；不是界面美化改写业务。上游补丁总表由主会话登记。

## 定向验证

通过桌面共享模块的正式模板加载、帧处理器及 `AndroidLabyrinthExEncounterResolver` 离线回放完整真实截图：页面为 `BATTLE_CHALLENGE`，难度 `NORMAL`，`challengeDifficultyResolved=true`，`extremeChallenge=false`。没有连接或操作模拟器，没有启动游戏任务。

| --- | ---: | ---: |
| 普通后缀 | 0.7632069651 | 0.9087419924 |
| 极难后缀 | 0.4976487126 | 0.5691471005 |
| 挑战页标题 | 0.9117499708 | 0.9117499708 |

新增 3 项 `LabyrinthChallengeSuffixResolutionTest` 全部通过：

- 真实 720p 标题裁片：原处理无法确认，修复后按原门槛确认为普通。
- 仓库内普通／极难模板分别独立生成 720p、900p、1080p 样本，6 个组合均分类正确。极难样本为合成缩放样本，不是真实 720p 极难截图。
- 空白标题保持 UNKNOWN；两种文字等量混合时两分约为 0.9048/0.9055，虽然各自超过最低分，仍因差值不足保持 UNKNOWN。

现有 `LabyrinthExChallengeDetectorTest` 5 项通过，包含弱分数、接近分数拒绝及 EX 结构判定。首次运行的新测试因构造器要求全部锚点而失败，补齐无关锚点占位后仅重跑这 3 项，通过。未进行全量回归或 Android 独立构建；打包与实机验收由主会话完成。
