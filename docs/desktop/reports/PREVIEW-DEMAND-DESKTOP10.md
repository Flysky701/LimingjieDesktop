# desktop.10 预览按需生成

日期：2026-10-27。版本：**1.0.18+desktop.10 测试候选版**。基于 desktop.9，仅优化预览链路；待用户测试后发布。

## 本轮依据

desktop.9 的约 60 秒本机采样中，连接两台设备、一台运行任务：助手平均 CPU 3.47%，采样峰值 12.60%，结束时私有物理内存约 2,080 MiB。运行设备进程约 1,352 MiB，空闲设备约 267 MiB，主界面和启动器约 460 MiB。CPU 按整机 32 个逻辑核计算，不包含模拟器或 ADB。此数据是旧版短时观察，不能作为新版收益或泄漏结论。

代码检查发现：选中的设备即使显示日志，仍会编码和传输预览；后台设备虽已不传预览，捕获线程仍为预览复制完整像素数组。

## 本次变更

- 画面展开且当前运行页可见时，才订阅该设备的预览。
- 显示日志、收起画面、切换设备或全局页面、最小化或隐藏主窗口时，停止预览的像素复制、PNG 编码与传输，并释放旧预览引用。
- 重新显示画面后，由后续截图生成新预览；任务截图、识别分辨率、识别频率、任务控制及日志更新不随预览隐藏而停止。
- UI 转换画面时移除一次不必要的数组复制；`BufferedImage.setRGB` 仍创建自身像素副本。
- 诊断的最近截图时间独立于预览显示，关闭预览后仍能记录捕获是否继续。

1920×1080 的一份 ARGB 像素数组为 8,294,400 字节（约 7.91 MiB）。隐藏预览后可省去周期性的这份数组复制，以及选中设备原本会进行的缩放、编码、传输和解码。该计算只说明临时分配来源，不代表常驻内存会下降相同数量，更不等于整机性能实测收益。

## 定向验证

21 项相关检查通过，无失败或跳过：捕获预览开关 1 项、共享运行页 UI 7 项、子进程通信 4 项、预览解码 4 项、真实应用图的离线集成 5 项。

覆盖隐藏时识别继续接收帧、恢复后得到新画面、折叠和展开、切换设备和页面、窗口隐藏后恢复、进程连接前的订阅保存、快速切换订阅，以及任务停止和资源释放。离线识别使用项目已有图片与模拟设备，不连接真实账号或操作游戏。

尚未对 desktop.10 进行同场景整机 CPU／内存对比。当前用户正在运行的程序不自动关闭或替换。

## 对比建议

完成当前任务后，再启动新包。采用相同模拟器数量、相同任务和相同页面，分别观察日志页、展开画面及最小化时的助手占用；预热时间保持一致。先确认任务和日志持续更新，恢复窗口后画面能刷新，再比较 CPU 平均值和内存变化。

desktop.8 基础包和 desktop.9 修复包保留。本轮未改识别策略、共享 OCR、状态协议的数据内容或任务行为，未推送或发布。
