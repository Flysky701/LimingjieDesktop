# 黎明界助手 Windows 桌面版

适用版本：**1.0.18+desktop.7**。文档核对日期：2026-10-26。

桌面版是社区移植，业务代码来自 [wbero/limingjie-assistant](https://github.com/wbero/limingjie-assistant)。账号、任务、策略和运行控制都在 Windows 窗口内完成；模拟器只运行游戏，无需安装安卓版助手。

当前交付为本地候选版。D7 已完成共享数据、设备运行页、实际打包后台进程等定向离线验证；此前版本也有窗口操作和实际模拟器连接记录。但 OCR 现有 15 个真实样本有 14 个解析正确，尚未达到 95% 的项目门槛，样本总量也未达到 80 条；低分辨率小数字漏读已修复，系列列表计数仍有漏读。完整账号登录、验证码、游戏循环和双模拟器同时执行真实任务尚未验收。请先使用只读识别核对具体画面，不将自检通过视作游戏流程已经通过。

本机 MuMu 的标题页动画在1280×720和推荐的1920×1080下，都曾被共享识别器误报为战斗失败。两次复核均只读，未点击或登录。额外精确抓帧已确认这是共享上游原有的颜色判定缺陷，桌面像素和模板资源一致；按项目边界保留原规则。无战斗上下文时现有逻辑会停止，不点击结束或重试。当前不建议直接开启真实游戏自动化，需先解决该缺陷并完成实际场景验收。

## 安装与启动

需要 Windows 10 1809 或以上版本 / Windows 11 x64、至少 4 GB 内存，并为模拟器和游戏预留额外内存。发行包自带 Java 21 运行环境，不需要另装 Java 或 Python。

1. 下载 ZIP 和同名 `.sha256` 文件。在 PowerShell 中运行 `Get-FileHash .\LimingjieAssistant-desktop-<版本>-win-x64.zip -Algorithm SHA256`，与校验文件核对。
2. 解压整个 `LimingjieAssistant` 文件夹到可写位置，例如 `D:\Tools\LimingjieAssistant`。不要直接在压缩包内运行，也不建议放在 Program Files。
3. 双击 `LimingjieAssistant.exe`。未经代码签名的版本可能触发 SmartScreen；确认来源和 SHA-256 后，可按 Windows 提示选择「更多信息 → 仍要运行」。不要绕过来源不明或校验不匹配的文件警告。
4. 首次向导展示上游使用风险和模拟器准备步骤。连接设备可以稍后进行。

发行包带 `portable.flag`，数据保存在 exe 同目录的 `data`。移除该标记后默认使用 `%LOCALAPPDATA%\LimingjieAssistant`；也可用 `--data-dir <目录>` 明确指定。目录不可写时会说明原因，不静默换位置。同一数据目录只允许一个实例。

## 共享数据与设备运行页（desktop.7）

一个窗口提供「运行、账号、策略、设备、记录、设置」六项导航。账号库、凭据、账号配置、策略与汇总记录共用，只有「运行」页按设备分标签。在「设备」页连接模拟器、绑定共享账号后，点击「打开运行页」；运行页的「＋ 连接设备」也会带你到设备管理。每台设备有独立后台进程与任务状态，切换标签不停止其他设备。

F5 开始、F6 暂停/继续、F7 停止只在当前运行页处理；配置未保存或完整配置页打开时不能启动，账号、策略等全局页面不处理这些运行快捷键。「停止全部」作用于所有设备。后台设备需要验证码时显示对应标签提醒，切回该页处理。运行期间不能换绑账号或断开设备，关闭运行标签会先确认停止；其他设备继续运行。有未保存修改时会提示丢弃，切换视图则保留草稿。

主数据目录继续保存共享账号、账号配置、策略和汇总记录；其旁的 `<主数据目录名>-run-tabs` 保存窗口状态、设备会话元数据和 `sessions/<会话ID>` 运行配置与缓存。设备进程使用凭据和 SDK 会话时只保留在内存中。新运行目录首次继承原主目录已保存的任务目标与任务选择，以后独立保存任务配置。不会自动导入 desktop.6 各 profile 的账号或更改旧目录。

重开助手不会自动连接设备或开始任务。同一已核实启动身份下，重新连接可恢复原运行配置与账号绑定；模拟器重启后需重新确认绑定。同一模拟器的多个 ADB 地址合并显示，同一账号先按共享账号 ID 互斥，正常登录后再按真实 UID 互斥，不再要求先手动读取开局才能确认身份。绑定不会切换模拟器内的游戏登录账号，开始前仍须人工确认两者一致。

全局策略保存后供所有设备的下一次任务启动使用；运行中的任务保持启动时的策略快照。记录页统一汇总，并可按设备、账号筛选。运行目标与任务选择保存在各设备运行页，账号刷开局配置则随共享账号保存。

## 模拟器准备

推荐 MuMu 12 或雷电模拟器 9。批量自动执行和执行入口流程要求游戏实际画面为 **1920 × 1080 横屏**；启动前不满足该尺寸会被拦截，请在模拟器中修改分辨率、返回游戏后重新检查。程序按截图尺寸判断，不会将模拟器报告的 1080 × 1920 设备方向误当成不兼容。其他尺寸仍可连接、预览和只读识别，但不表示自动点击已受支持。

在模拟器设置中打开 ADB 调试：MuMu 可在设置的其他/ADB相关选项中查看本机连接端口；雷电在设置的其他设置中开启 ADB 调试。版本不同菜单名称可能变化，以模拟器显示为准。多开实例端口不同，请使用目标实例对应的本机地址。

进入助手「设备」页，点击「重新检测」，选择在线设备并「连接」；也可填写序列号 / `127.0.0.1:端口` 后点击「添加并连接」。ADB 不随发行包捆绑；在「高级：ADB 工具与路径」中选择模拟器自带的 `adb.exe`，或下载官方 Platform Tools，更换路径前须断开设备。首次连接会读取设备画像、游戏包版本/签名并测量截图速度；准备期间显示进度并禁用重复连接。断开会话使用「重新连接」，已连接设备可进入「设备详情」查看测速与触控信息。切换页面不会取消连接准备。

设备页和首次向导共用检测结果，重新进入页面不会反复探测。新发现设备需在 ADB 中在线且已授权，同一实例的多个地址合并显示；已保存的设备会话仍可能显示为「离线」或「未连接」，不代表已连接成功。模拟器后启动或空列表需要刷新时，点击「重新检测」；运行中的 MuMu 会通过其管理器提供的实际本机端口补齐 ADB 登记，不猜测或扫描端口。其他尚未登记的实例可填写其 ADB 端口。

连接时依次显示安装信息核验、截图测速和触控准备。首次读取游戏包仍完整验证签名；之后在设备、Android 版本、包版本、更新时间、安装路径及文件大小/修改时间均未变化时复用已验证的签名缓存。安装信息改变或缓存损坏时重新核验；缓存不包含账号密码。

MaaTouch 为默认触控方式；不兼容时可切换到兼容模式后重新连接。兼容模式使用 ADB 输入，速度与按住语义有所不同。「测试点击」只允许在非游戏前台页面中央点击一次。

## 日常使用

1. 在账号库新增账号并明确选择服务器。B 服填写登录账号与密码；渠道服填写 `uid` 与 `access_key`。凭据以当前 Windows 用户的 DPAPI 加密保存。更换服务器必须重新填写密码。
2. 在「设备」页连接模拟器并绑定账号，再打开其运行页。绑定只选择助手使用的凭据，不切换模拟器里的游戏账号。核对二者一致。
3. 可先「登录并读取」检查当前开局；这仍是核对开局的入口，但不再是首次账号身份确认的强制步骤。人工验证码由系统浏览器中的 Geetest 官方组件完成；无法自动打开时复制对话框链接。登录账号和密码不会传入验证页面。
4. 「运行」首页直接设置公会目标次数、计数方式、难度及常用刷取参数，在底栏保存或取消；下次打开会恢复保存值和任务选择。其他路线、Boss 与撤退设置在「高级配置」中。未保存时不会启动；允许彻底撤退时仍需确认，请核对需要保留的开局。
5. 「策略」页包含编组、开局阵容和角色个人评分。所有设备共用已保存策略，下一次任务启动生效；取消不保存。恢复默认与离开未保存修改时会确认。
6. 「只读识别」只分析画面，不发送点击；「执行入口流程」和批量自动执行会改变游戏状态。批量任务通过启动检查后，会检查所选模拟器上当前账号服务器对应的 PCR 进程；存在时先关闭并确认退出，再进入批量流程，失败则停止启动。运行时保持模拟器游戏在前台，并在游戏黎明界设置中关闭「播放角色加入动画」。

画面任务可在当前运行页或托盘暂停、继续、停止；网络刷开局只提供停止。任务启动和停止阶段会禁用冲突操作。有任务或未保存修改时关闭主窗口，可选择最小化继续、停止全部并退出或取消；无任务且无草稿时正常退出。托盘另有「停止全部」。

## 常见问题

| 现象 | 处理 |
|---|---|
| 找不到设备 / unauthorized / offline | 确认模拟器已启动、ADB调试开启、端口对应目标实例；必要时在模拟器中完成调试授权，再重新检测。助手不会代点系统授权 |
| ADB版本冲突 | 断开后选择对应模拟器自带ADB，避免多个来源同时争用服务；保留具体错误信息 |
| 截图慢、持续黑屏 | 查看截图p50/p95，保持模拟器可渲染，避免最小化；调整模拟器渲染设置后重新连接测速 |
| 触控未就绪 | 重新连接；必要时改兼容模式，先在非游戏页面测试一次点击 |
| OCR初始化失败 | 查看日志确认模型和原生库未被删除；重新解压完整发行包 |
| 原生DLL加载失败 | 安装微软官方 Visual C++ 2015–2022 x64 Redistributable，并确认系统为x64；不要从不明网站单独下载DLL |
| 界面空白 | 退出后设置环境变量 `SKIKO_RENDER_API=SOFTWARE` 再启动，尝试软件渲染 |
| 网络失败 | 在设置页选择系统代理或直连，并手动测试SDK连通性。Java仅支持静态系统代理，不支持PAC自动配置脚本 |
| 复制数据后密码无法读取 | DPAPI密文绑定原电脑/Windows用户环境；在新环境重新填写密码，不会回落明文 |
| 数据库已下载但未生效 | 文件被占用时保留候选，关闭并重启助手，下一次读取前尝试安装 |
| 重启模拟器后账号未自动绑定 | 启动身份已变化，在设备页重新连接并确认账号；不要仅凭旧 ADB 地址判断设备身份 |
| 另一台设备修改策略后当前任务没有变化 | 运行任务固定使用启动时的策略，保存的全局策略在下一次启动生效 |

## 日志、备份与自检

「运行」页右侧查看当前设备日志与画面；「记录」页提供汇总记录和「日志与诊断」入口，可打开本机面板、导出原格式诊断 ZIP、打开日志目录及查看崩溃记录。导出到你选择的位置，不自动上传；排查设备任务时还应保留该设备运行页的日志与会话目录。分享前检查截图和日志中的个人信息。诊断面板只绑定 `127.0.0.1`，地址以界面显示为准，无需给 Android 助手设置端口转发。

关闭助手后备份整个主数据目录及相邻的 `<主数据目录名>-run-tabs`。前者含共享账号、账号配置、策略与记录，后者含各设备的任务配置和会话信息。保留数据库及可能存在的 `-wal` / `-shm`，不要只复制一半。设置损坏会保留 `.corrupt-*` 原文件并提示；确认损坏的账号库会备份到 `databases/corrupt-*` 后重建，需重新添加账号。不要用旧 Python 项目的数据覆盖这里。

可运行 `LimingjieAssistant.exe --self-test --report report.json --data-dir "D:\测试 目录\self-test-data"` 执行无需游戏账号的运行环境检查。TLS检查只握手，不发送业务请求；断网会记录跳过。测试不代表真实账号、验证码或完整游戏流程已经验证。

源码仓库的当前版本记录见 [D7 交付报告](docs/desktop/reports/SHARED-RUN-TABS-D7.md)。便携包中的「用户验收清单.md」保留此前设备与游戏检查；其中 desktop.6 的独立策略和首次手动确认要求已被本说明中的共享数据流程替代。

以下为上游「使用风险」原文：

- 本项目与游戏官方无关。自动操作和非官方接口访问可能带来账号限制或封禁风险，不保证账号安全；使用前请自行确认游戏相关规则。
- 角色选择、商店购买、刷新、战斗及彻底撤退会改变真实游戏状态，可能消耗资源或丢失当前开局。启动前核对账号、策略和撤退选项。
- “已执行”仅表示操作已派发，不代表游戏已完成预期操作。当前角色列表滚动、边界回弹、识别与流程衔接仍可能异常，需要人工接管。
- 请勿公开账号密码、访问令牌、验证码、未脱敏日志或包含个人信息的截图。交流群不是账号托管渠道。
