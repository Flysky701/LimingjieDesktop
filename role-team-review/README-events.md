# 黎明界事件决策模拟说明

本页说明离线审阅器的事件估值模型。正式任务使用 Kotlin 事件识别与决策，操作方法见[桌面指南](../README-desktop.md)，数据准备见[战斗模型说明](README-combat-model.md)。

## 1. 数据来源

审阅页直接读取本目录已入库的 `data.js.eventCatalog`。Python 生成器原先从以下本地数据库读取事件：

```text
pick/autopcr-android/app/src/main/python/cache/db/202604021043.db
```

中的：

```text
labyrinth_event
labyrinth_event_choice
```

生成 `data.js.eventCatalog`。该旧库需自行准备，缺少时事件目录为空。`--database` 用于角色和战斗数据；事件目录仍从上述固定路径读取。

当前已入库的 `data.js` 快照包含：

```text
22 个事件状态
41 个可选项
```

包括职能角色池、NORMAL/EXTREME 战斗、石板、迷路、猜拳、宝箱、活动会场、钓鱼、料理与老虎机完整三段事件链。

---

## 2. 职能事件映射

游戏事件文字与角色审计表职阶映射如下：

```text
坦克型   -> 掩护者
治疗型   -> 治疗者
强化型   -> 增幅者
增益型   -> 增益者
减益型   -> 减益者
干扰型   -> 妨碍者
攻击型   -> 攻击者
破防型   -> 破防者
```

例如 `1102` 的：

```text
强化型随机角色×2 + α币200
vs
增益型随机角色×2 + α币200
```

不会按固定优先级决定，而是根据当前已获得角色计算两个池子的**当前边际价值期望**。

每个未获得角色都会使用当前 V2 队伍模型估计加入阵容后的提升；事件池只用于求期望，不把用户评分直接作为最终池子答案。

为了避免几十名候选导致浏览器组合爆炸，事件池估值最多保留当前已有角色中个人搜索优先级最高的 12 人参与边际计算。具体三选一仍使用实时角色选择器的完整逻辑。

---

## 3. 角色奖励类型

当前支持：

```text
指定职阶随机角色×2
随机职阶随机角色×2
随机职阶角色自选×1 / ×2
全角色随机×2～4
全角色自选×1 / ×2
指定角色“纯”加入
```

对于 `×2～4`，数据库没有给出数量概率时，事件模拟器暂按期望数量 `3` 估值，并在页面说明中明确标记。

---

## 4. 遗物奖励如何估值

数据库确认普通遗物的基础结构：

```text
★1 -> 1 印记
★2 -> 2 印记
★3 -> 3 印记
```

同时 `labyrinth_relic.price` 中普通遗物价格为：

```text
★1 1800 α币
★2 2800 α币
★3 3800 α币
```

网页事件模拟器默认使用以下遗物路线估值；正式任务以已保存策略和 Kotlin 实现为准：

```text
先补 4 加速
再补 4 会心
再补 4 守备
完成 4/4/4 后集中一个印记冲 15
弱体接近 15 时允许转追弱体
```

因此同一个“随机★2遗物”，在：

```text
加速3 / 会心4 / 守备4
```

时的价值，会高于已经：

```text
加速8 / 会心8 / 守备8
```

但离任何 15 层都很远的情况。

事件效用只是内部排序单位，不是伤害百分比。

---

## 5. α币如何与遗物比较

为了让金币选项能与角色/遗物放在同一排序中，当前使用：

```text
1800 α币 ≈ 当前最需要的一件普通★1遗物的内部效用
```

这是基于数据库中的普通★1遗物价格建立的转换尺度，而不是宣称游戏中所有商店情况下 1800 币都必然等价于一件指定遗物。

## 6. 战斗事件

四档斗技场事件均已加入：

```text
NORMAL 200  vs EXTREME 300
NORMAL 300  vs EXTREME 450
NORMAL 400  vs EXTREME 600
NORMAL 500  vs EXTREME 750
```

当前页面提供：

```text
NORMAL 预计胜率
EXTREME 预计胜率
```

默认只是预览值，用户可以按当前难度/阵容调整。

没有实际敌人战斗模型前，不把 EXTREME 胜率伪装成精确自动预测。

---

## 7. 概率事件

### 石板

已支持：

```text
50% α币1500 / 50% α币2000
50% 随机职阶自选1 / 50% 全角色自选1
50% ★2遗物 / 50% ★3遗物
```

### 迷路

已支持：

```text
固定 α币1000
vs
50% ★1遗物 / 50% 随机职阶随机角色×2
```

### 猜拳

三个选项奖励结构完全相同，因此从策略角度视为等价。

页面只为显示期望值暂按“对方三手等概率”估算，不用这个假设区分石头/剪刀/布。

### 宝箱

已支持：

```text
α币2000
vs
★1～3随机遗物
```

数据库文字未给 ★1/★2/★3 的出现概率，因此暂按三档等权估值，并明确标记为假设。

### 活动会场

已支持：

```text
α币2000
vs
纯加入 + 全角色随机×2～4
```

## 8. 三段连锁事件

### 钓鱼

```text
第1段：50% ★1 + 进入下一段
第2段：25% ★2 + 进入下一段
第3段：10% ★3
```

### 料理

```text
第1段：50% 进入下一段
第2段：直接拿随机职阶随机×2，或 50%继续
第3段：随机职阶自选×2，或 50%全角色自选×2
```

### 老虎机

```text
第1段：50% α币2000并继续
第2段：结束，或 50% α币4000并继续
第3段：结束，或 50% α币8000
```

连锁事件使用递归期望值：

```text
当前选项价值
= 成功概率 × (本段奖励 + 下一段最优选择价值)
+ 失败概率 × 失败补偿
```

用户提供的 β2 版本总结指出失败后获得 `500 α币`，当前模拟器按此规则处理。该补偿并非 `labyrinth_event_choice.description` 每条都直接写出，因此在未来国服版本变化时需要再次验证。

---

## 9. 数据库条件字段

部分选项带：

```text
condition_type = 1
condition_value = 2000 / 4000
```

页面原样展示条件字段。`condition_type=1` 的含义待核实，执行层同时依据按钮状态和页面反馈判断可用性。

---

## 10. 当前 Kotlin 自动化接入

当前调用路径：

```text
AndroidLabyrinthEventChoiceResolver
  -> 事件与选项观测
  -> LabyrinthEventChoicePlanner
  -> Select(actionSafe=true) 或 Wait
  -> LabyrinthEntryRecognitionSession 在自动执行模式派发对应按钮动作
```

规划器按当前角色、遗物层数、策略胜率与选项效用排序；只读识别不会点击。允许自动动作还需满足：

- 事件文字已连续稳定确认，推荐选项有可靠按钮映射。
- 按钮达到可用亮蓝置信门槛；灰蓝或条件不足时保留推荐说明，但不直接点击。
- 职阶角色池选项所需的已有角色资料完整。
- 已点击但页面不变化的选项会被排除；重试有上限，所有选项都不可执行时等待或停止。

识别样本与评估结果见 [OCR 说明](../desktop/ocr/evaluation/README.md)。
